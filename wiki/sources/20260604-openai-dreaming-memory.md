# OpenAI Dreaming V3：ChatGPT 记忆从"功能"到"系统"的演化

## 证据边界（2026-11-28）

直接核对本地Raw 89行及[2026-06-04官方发布](https://openai.com/index/chatgpt-memory-dreaming/)的演进、三项评测目标和扩展章节。V3是发布时比较代际的名称；官方报告Free用户dreaming计算量约缩减5倍，但没有公开内部算法、索引、时间字段、完整样本及可复现实验协议。本轮不读取图表估算分数。当前[Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)说明记忆摘要是高层视图、并不穷尽来源；纠正或不再提及不同于删除原始信息，完全移除需处理记忆摘要及所有原始来源，更新传播需要时间。个人账号训练使用取决于数据控制，Business/Enterprise/Edu等默认不训练；敏感信息仍可能进入记忆。按套餐、地区和工作区配置变化，不将发布时产品功能写成所有账户当前状态。历史Q-A和商业分析保留为待验证推论，不把它们当作官方陈述。

## 编译摘要

### 1. 浓缩

- **核心结论 1**: ChatGPT 记忆从 2024 的"用户显式说记住"（saved memories）→ 2025 的"后台自动整理"（Dreaming V0）→ 2026 的"独立可扩展记忆系统"（Dreaming V3）——记忆从"功能"升级为"持续可观察的状态"
  - 关键证据: 2024-04 saved memories launched（"remember that..."）
  - 关键证据: 2025-04 Dreaming V0（后台从聊天历史整理记忆）
  - 关键证据: 2026-06 Dreaming V3（独立可扩展架构）
  - 关键证据: V3以staleness、correctness、scalability为设计目标，不意味着三类问题已经解决
  - 关键证据: Memory summary page 让用户可审可改

- **核心结论 2**: 记忆系统演化的核心动机是"LLM 产品的'会话'概念被改写"——跨会话个性化可利用持续更新的记忆状态；会话、任务和授权边界仍独立存在
  - 关键证据: 官方2026-06-04称Free用户所需dreaming计算量约降至原先1/5，使其具备逐步推广条件；非所有套餐、全部记忆操作或整体服务成本的5倍改善
  - 关键证据: Memory summary page 把后台合成的记忆暴露给用户
  - 关键证据: "dreaming" 借用人脑睡眠期记忆整理的隐喻
  - 关键证据: 后台综合是产品描述，不披露具体调度频率、存储及一致性实现

- **核心结论 3**: 持续记忆可能降低重复提供背景的成本并支持长期协作；产品定位、切换成本、数据治理及用户行为是本库分析假说，不是发布文章证实的商业或法律结果
  - 关键证据: 工具 vs 持久助理的产品形态差异
  - 关键证据: 切换成本可能受可导出、可迁移性和任务历史影响，未测量
  - 关键证据: 数据使用权、控制权及可携带性需按服务条款与实际机制分别判断
  - 关键证据: 用户纠正记忆与训练授权是不同过程，不能从纠正动作推出训练用途

### 2. 质疑

- **关于"Dreaming V3 是独立可扩展系统"的质疑**:
  - **成本/收益**：后台综合的收益、调度频率及成本因使用模式而异；未披露真实单用户成本或盈利数据。
  - **staleness 是核心难题**：单纯"加时间戳"不够，变化不是函数式可预测的；"主动询问"违反"不打扰"原则
  - **summary 的失真**：当记忆量巨大（用户用 5 年），summary page 仍要降维——可能丢失关键细节

- **关于"用户可审可改"的质疑**:
  - **summary of summary 失真**：暴露给用户的是 summary，summary 本身就有信息损失
  - **用户不愿意看**：用户是否查看、纠正及频率需要实测，本文未报告
  - **策略性修改**：需区分事实纠正、偏好表达与行为指令；修改偏好本身并非错误数据

- **关于"持续记忆对开发者生态"的质疑**:
  - **生态分裂**：第三方应用调用 ChatGPT 时，记忆不会自动跟进
  - **集成 vs 自建**：自建或集成的权利、成本与可移植性取决于具体接口和合同；本文未披露可通用集成的ChatGPT记忆API
  - **lock-in 风险**：若未来出现广泛集成接口，可能影响生态竞争；未证实事实标准已经形成

- **关于"训练数据回授"的质疑**:
  - **隐私 vs 价值**：训练使用须依据当前数据控制及服务政策，不能从用户修改记忆推断其训练授权或实际使用
  - **个人信息暴露**：当用户修改"关于我"的内容（家庭住址、健康状况），被用于训练是否合规？
  - **监管风险**：欧盟 GDPR / 中国个人信息保护法对"训练数据"有明确约束

- **关于"用户身份二分"的元质疑**:
  - **自我实现预言**：长期看，用户会按 AI 画像调整自己——"用 AI 越久，AI 越准"和"用 AI 越久，你越不是你自己"是同一件事的两面
  - **修复路径**：用户主动纠正 AI 画像（频繁看 memory summary）可压制偏差，但需耗费认知带宽

### 3. 对标

- **跨域关联 1 (操作系统)**: "Dreaming 后台进程"与 OS 的 daemon/后台服务同构——在用户不在时做整理，对用户不可见但持续。这与 [[Multi-Layer-Memory]] 中的 L3 历史检索（按天分日志 + 语义检索）有相似分层
- **跨域关联 2 (产品)**: "持续助理"的产品形态与 SaaS 模式、订阅经济形成连续光谱——从"用完即走"到"持续在场"是订阅商业模式的终极形态
- **跨域关联 3 (记忆研究)**: "Dreaming" 借用 Benjanin Bloom / Robert Stickgold 等人关于人脑睡眠期记忆巩固的研究——睡眠巩固为类比，未核文中所列具体研究者的直接来源或与实现的因果关系
- **跨域关联 4 (个人数据)**: "用户对 AI 关于自己的内容有修改权"与 [[Memex]] 范式的"个人数据归属"形成连接——LLM Wiki / Obsidian Wiki 与 ChatGPT Dreaming 是个人数据主权的两种实现路径
