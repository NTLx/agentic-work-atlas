## 编译摘要

### 1. 浓缩

#### 一、训练数据的价值在于模型当前能力边缘，而非难度越高越好

- **原文（00:00–00:15、06:46–07:55）**：Greenberg 将专业强化学习环境描述为由任务、初始数据和验证器构成的系统。太简单的任务对训练价值有限；远超当前能力的任务可能更适合评测；应寻找略高于当前水平、模型仍能获得学习信号的任务。这里是受访者的经验性难度校准方法，而非训练算法定理。
- **综合判断**：将 `capability baseline → difficulty sweep → rollout/reward distribution → small training ablation → held-out gain` 作为任务准入测试。难度是相对于具体模型、Harness、动作空间、预算和奖励设计的属性，而非固定标签。难题即使暂时不可训练也可能具有诊断价值；容易任务也可能用于基础能力保持、覆盖或课程学习。
- **与既有材料对标**：[[20261109-latentspace-handshake-frontier-labs-data]] 讨论专业任务的可执行环境、训练试验和 held-out；G2i 补充供给方如何选择难度带。两次访谈均为供应商自述，不能当成独立实验证明某个成功率阈值。
- **边界**：没有公布成功率区间、训练算法、成本、模型版本或难度消融。不可机械制定“过难=eval、过易=无价值”规则，更不可将训练和保留评测集混用。

#### 二、专家数据生产是另一类工程工作：任务构造、可验证性和专业判断缺一不可

- **原文（02:42–06:46）**：受访者回顾 2023–2024 年数千工程师参与的项目，称近两年复杂任务制作转向 Staff 级工程师、数据集设计与专业 taste；机器人领域则可能重新需要大规模采集。G2i 从招聘网络转向数据供应，强调既有高质量工程师社区的作用。
- **原文（06:46–12:22）**：生产软件与 RL 环境的质量目标不相同；后者还必须设计 seed data、任务和 verifier。G2i 早期通过观察候选人用 Agent 写代码、讨论普通生产系统如何改造成 RL 环境来筛选，数据制作侧通过培训及实际任务是否达标决定继续合作。Greenberg 明确说自己已不掌握最新面试细节。部分项目贡献者后来成为团队负责人和正式工程员工。
- **综合判断**：人员能力评估应按实际产物与独立验收分层：领域正确性、环境复现、任务表述、评测覆盖、模型协作效率、质量审查。会使用 Agent 不等于有能力构造可靠 verifier；高级职级也不保证对特定任务有合适判断。
- **边界**：项目人数、人员转型和招聘经验属自述；不存在已验证的所有数据任务都需要 Staff Engineer 的规律。机器人采集与专业软件 RL 环境不能以同一种人员比例类推。

#### 三、采购从标准数据包走向针对能力缺口的迭代合作，但不是所有采购均独占

- **原文（12:24–16:24）**：Greenberg 描述实验室采购较传统大企业快速，先小额或试点项目、再放大，越来越希望供应商帮助定位能力缺口并迭代任务、说明和质量，而非只交付正确标签。受访者称当前质量溢价可能高于约 20% 的价格差；没有公开实际成交数据。身份核验、供应链安全、训练材料泄露、竞争项目重叠是其列举的风险。
- **原文（18:45–22:16）**：标准化货架数据可以合法按合约销售给多个客户，共享固定生产成本；客户有时接受非独占换取折扣。针对专有能力差距设计的数据可能具有独占溢价。受访者澄清，他所谓较成熟的内部运营主要是供应商管理及基础设施，而非已经完全自建全部数据生产。
- **综合判断**：将采购分为可共享基础数据、受许可限制的原始资料、专有任务/评测、定向训练环境和内部控制面。比较供应商时使用小规模验证、接受率、修订轮次、真实训练收益及来源合法性，而非只按标注数量或报价。企业可以自持业务语义、质量门、授权与关键验收，再选择外部供给；build vs buy 不必二选一。
- **边界**：快速采购与无 RFP 属其客户经验，不代表实验室没有合规流程。独占、转授权、保密及竞争冲突必须由实际合同决定；供应商管理成熟不能证明所有数据操作可外包。

#### 四、数据与算力是互补资产，不能只优化每个任务的采购单价

- **原文（22:16–23:46）**：主持人与嘉宾讨论后训练及数据相对算力的预算变化；约 2–3% 到 4–6% 属谈话中的行业估计，50% 是论证性设想而非实测预算。算力已经到位时，等待更优数据也可能产生空闲成本，因此实验室在质量、交付速度、针对性和可用量之间取舍。复杂长程任务无法保证短时间按需大量交付；现成数据可更快获得，但可能偏离能力缺口。
- **原文（23:46–24:52）**：数据单位可能是任务或标注，任务的上下文、难度和 rubric 数量不同，受访者称 AHT（Average Handling Time）常用于定价；以 Staff 工程师每小时 250 美元、10 小时的任务作为举例。部分交付会被买方退回要求修订，受访者举例约 80–90% 接受、其余迭代，不是经审计的平均接受率。
- **综合判断**：可比较的单位应为**达到验收要求的可用任务及其独立学习收益**。计入专家时间、环境实现、QA、修订、算力等待、数据许可、存储和治理成本；用 `accepted task cost` 与 `cost per held-out capability gain` 分别衡量采购效率与训练价值。示例 10 小时 × 250 美元/小时 = 2,500 美元，仅为假设工时成本，非实际报价或包含所有成本的合同价格。
- **边界**：不能从访谈估算推出整个行业预算分布、最优 data/compute 比率或数据质量与模型性能的普适比例关系。

#### 五、真实跨系统业务数据的价值在于一致性与时序，而不只是数据量

- **原文（24:54–27:44）**：受访者讨论公司原始数据交易与 Computer Use，举例模型在 Slack、邮件、CRM 等系统切换时将近似名字的不同人混淆。跨 GitHub、Linear 等工具的同一项目记录具有业务连贯性；持续时间、团队规模与多个系统之间的对应关系也是供给方看重的属性。访谈中提到数 TB、十余人等门槛，是市场观察而非经验证的采购规则。主持人关于监控员工屏幕出售数据的说法是带有自嘲的设想，不能当成推荐。
- **综合判断**：企业训练/评测环境更应保留可审计的实体映射、事件因果与时间关系、状态转换、工具权限和真实歧义，而非无约束复制全部内部数据。用合成或严格脱敏的业务世界重现近似姓名、同名项目、重复订单、异步同步、来源冲突等困难；分开验证实体解析、任务执行与最终业务结果。
- **治理边界**：员工通信、客户信息、个人健康资料、专有代码及科研数据不得因可能具有训练价值便被推定可收集、训练、出售或跨境传输。先核实权属、合同限制、合法处理依据、授权范围、最小化、隔离、删除和审计能力；高风险数据默认不用于外部训练。原文对原始公司数据销售的乐观观点不等于法律或伦理许可。

#### 六、市场增长叙事伴随高买方集中度；Neo labs 与垂直化需求仍需验证

- **原文（01:17–02:34、14:18–15:12、16:24–18:45、27:44–30:30）**：Greenberg 自述上年约 1,500 万美元规模、本年预计约 1 亿美元，公司盈利且未获 VC 支持；约五六家前沿实验室客户，下一年可能增长约三倍。谈及约 100–150 亿美元以上可触达市场、更多新实验室与企业内部 intelligence，以及机器人、3D 世界模型、CAD、机械工程、芯片、法律金融等未来需求。受访者也明确说市场规模和经常性收入问题尚早。
- **综合判断**：分离已实现营收、当年预计规模、下一年情景与 TAM；评估供应商时关注客户集中、合同期限、续购原因、毛利、采购周期、专家产能、数据许可和可迁移能力，而非直接用前沿实验室支出外推整个企业市场。垂直 Agent 的需求也可能主要落在 Harness、检索、工具和评测，不一定需要训练模型。
- **边界**：未见财务报表、订单口径、客户构成、市场测算方法和续约数据。访谈里的规模指标不标注为 ARR；未来增长与市场方向为预测，不是已发生事实。

#### 七、训练数据厂自身也依赖 Agent 编排，但产品宣传与验收分开

- **原文（08:16–09:01、30:30–32:21）**：G2i 表示使用自研 ORC 进行软件开发、多 Agent 协作及部分安全工作，并称其为支持企业部署的 Rust 编排框架、提供 SDK、支持多模型和 Agent 间通信等。官方 show notes 链接为 https://orc.ai/；末段自动字幕出现不同拼法，不能据此认定不同产品。
- **综合判断**：用 Agent 生产训练环境仍须受确定性任务状态、独立验证器与人工专业验收约束。编排平台本身的可用性、治理、权限、移动端和部署能力应根据产品文档与实际测试独立评价。
- **边界**：本次没有测试 ORC，不把受访者对其工业、军政或安全场景的表述当成已验证部署能力；不对其他编排产品做未经验证的功能排名。

### 2. 质疑

1. **难度不是训练有效性的充分条件。** 奖励稀疏、错误 verifier、任务泄漏、重复分布或模型预算变化均可导致无效或错误学习。评测集应独立保留，并控制数据重叠。
2. **自报指标与营收口径。** 1 亿美元为本年预期而非已审计收入，三倍增长为预测；不能写成 ARR 或确定下一年营收。五六家客户意味着需关注集中风险，但缺各客户金额，不能计算真实集中度。
3. **AHT 衡量投入，不等于训练收益。** 长任务可能成本高但效果弱；短任务也可能具备关键能力覆盖。接受率不代表 held-out 泛化。要测真实训练消融及独立结果。
4. **生产软件与训练环境并非质量标准完全相反。** 可重放、种子状态、verifier 和任务隔离是环境额外要求；安全、正确性、可维护性仍适用。受访者没有给出可普遍接受的反模式清单。
5. **跨系统数据的“真实”不等于合规或准确。** 原始数据有噪声、错误权限、敏感信息与重识别风险，真实身份也未必适合训练；可控模拟世界可能更适合验收。
6. **安全责任不能随外包消失。** 供应商集中、人员筛选、竞争冲突与数据泄露仍需合同、来源审计、隔离和访问控制。受访者举例不构成具体安全事件的独立证据。
7. **利益相关性。** G2i 既是数据供应商，也是访谈赞助商。采购规模、质量溢价和未来需求的说法属于直接市场参与者观察，不是代表性行业调查。
