## Explore [2026-08-31T11:22:38] · 验证器独立性与证据覆盖

- Mode: open exploration
- Trigger: `EX-001` 的四轴模型已把生成者/验证者的目标、证据、执行、时间耦合拆开，但仍没有回答：验证者是否看到了决定性状态，以及看见后是否能正确使用证据。
- Evidence posture: 下列网页为已核读、尚未剪藏的外部一手研究；本节的“独立性 × 覆盖/解释”关系、候选判据与实验设计均为 synthesized，不升级稳定 Entity/Topic。

### Evidence

- supports [AJ-Bench: Benchmarking Agent-as-a-Judge for Environment-Aware Evaluation](https://arxiv.org/abs/2604.18240) — 一手预印本构造了 155 个任务、516 条轨迹，覆盖 search、data systems 与 GUI，并把验证拆成信息取得、状态验证、过程验证。相同基座开启工具交互后，平均 F1 比无工具的 LLM-as-a-Judge 高约 0.13，但平均 F1 仍约为 0.72；论文将失败分为未调用/调用错误工具、误读工具输出、已有正确证据仍推理错误四类。交互轮数增加总体提升 F1，但不同子领域对交互预算和输入模态的敏感度不同。
- bounds [AJ-Bench limitations](https://arxiv.org/html/2604.18240) — 任务多数由既有基准改造而来；search 子域依赖外部网络，网络不稳定会影响复现。因此它支持“覆盖与解释是可分离的失败来源”，但还不能直接证明某一覆盖门是所有生产验证的必要条件。
- supports [A Statistical Framework for Auditing Behavioral Dependence and Induced Bias in LLM Judges](https://arxiv.org/abs/2604.07650) — 该研究在客观可验证任务上从模型错误结构估计行为纠缠，并把它与 judge 的过度背书关联；它研究的是黑箱模型输出/错误之间的依赖，不测量验证者是否取得了环境状态或是否正确调用工具。
- bounds [LLMs as a Jury: Cross-Model Consensus Can Outperform Process Reward Models for LLM Reasoning](https://arxiv.org/abs/2607.10139) — 跨模型共识在固定候选池、相同评分 harness 和静态答案选择上显示错误去相关与共享错误下界；这能检验模型间证据/错误耦合，却没有覆盖 live environment 中的状态与过程验证。

### Reasoning

1. 现有 `EX-001` 主要问“生成者与验证者是否共享盲点”。但共享盲点不是验证失败的全部来源：验证者可能没有拿到关键状态，也可能拿到了状态却误解工具输出，或在证据充分时仍推理错误。AJ-Bench 的失败分类把这三层从模型间相关性中分离出来。
2. 因此“跨模型/跨家族”只能优先削弱相关错误，不能推出证据闭包已经成立；“能访问工具”也不能推出覆盖有效，因为工具遗漏、错误调用和误读仍会留下漏报。
3. 新的候选边界是：有效保障至少受两类条件共同约束——**独立性**减少共同盲区，**覆盖/解释链**保证关键状态进入判定并被正确使用。二者的关系暂写为候选瓶颈模型，不把乘法形式或“最弱轴”升级成定理。

### 新问题

**EX-002：在控制模型能力与任务难度后，验证器的证据覆盖/解释链是否是独立于四轴独立性的第二个必要门？**

当前判断：已出现明确的研究缺口，但只有一个尚未剪藏的环境感知基准支持拆分，故保持 synthesized。它与 `CR-004` 的 observability 边界相连：`CR-004` 问系统能否观测运行时路径，`EX-002` 问验证器是否实际取得并正确使用与判定相关的状态/过程证据；二者不能互相替代。

### 证伪方向

- 在同一任务和同一模型上，静态轨迹与 live environment 的访问差异对 FPR/FNR、校准和拒答率没有稳定影响；说明“覆盖门”可能只是某些任务的实现细节。
- 在控制工具访问与证据覆盖后，仅切换同族/跨族模型即可解释全部剩余错误类型；说明 EX-002 与 EX-001 没有独立增量。
- 低覆盖的跨族 verifier 在环境/过程任务上稳定达到可交互 verifier 的召回率，并且错误不集中在工具遗漏、误读和证据后推理三类；可削弱“覆盖先于独立性”的候选顺序。

### 最小实验

在 AJ-Bench 的一个 DS 或 GUI 子域上，保持任务、轨迹、基座模型和判定规则不变，构造四格：

1. 静态轨迹 × 同族/单模型 verifier；
2. 静态轨迹 × 跨族 verifier panel；
3. 可交互环境 × 同族/单模型 verifier；
4. 可交互环境 × 跨族 verifier panel。

预先记录 FPR、FNR、校准/拒答率，以及工具遗漏、误读工具结果、正确证据后的错误推理三类失败。若跨族只改善相关错误而可交互只改善状态覆盖，两条轴具有独立增量；若一条轴能稳定消除另一条轴的失败类型，EX-002 或 `EX-001` 的独立性拆分需要收窄。当前这只是实验设计，不能把预期结果写成 evidence。

## Explore [2026-08-31T12:02:57] · Facilitator 主动升级的校准瓶颈

- Mode: open exploration
- Trigger: `20260831-agency-and-agents` 新增 Twilight Factory 设想：facilitator agent 主动判断何时、为何以及请哪些人介入。现有 `Escalation-Based-Human-Oversight` 已描述常规路径与例外路径，但把“识别人类何时更好”当作未展开的前提。
- Evidence posture: 下列网页为已核读、尚未剪藏的外部一手研究；选择性委派与消息 framing 的结构关系、候选问题和实验设计均为 synthesized，不升级稳定 Entity/Topic。

### Evidence

- supports [Human-AI Teaming Through the Lens of Calibration](https://arxiv.org/abs/2606.10906) — 一手预印本从校准角度分析 human-AI teaming：把预测委派给人或模型会把负担转移到决定“谁来预测”的 rejector；rejector 必须细致定位人类优于模型的区域，而当人类依赖系统不可见的额外信息时，这种路由会有不可约的 excess risk。
- bounds [An Empirical Analysis of Calibration and Selective Prediction in Multimodal Clinical Condition Classification](https://proceedings.mlr.press/v333/lopez26a.html) — 2026 年 PMLR 论文在多模态 ICU 多标签分类中发现，基于不确定性的 selective prediction 即使在标准指标良好时也可能降质；按类别误校准会让正确预测被赋予高不确定性、错误预测被赋予低不确定性，聚合指标会遮蔽该问题。该证据是特定临床任务的实证，不能直接外推到一般 Agent。
- supports [Role of Human-AI Interaction in Selective Prediction](https://arxiv.org/abs/2112.06751) — 一手人类实验显示，向参与者传达“系统决定升级”与否、以及是否展示模型预测，会改变最终判断；在其 camera-trap 任务中，展示 deferral status 有帮助，而展示错误的模型预测可能把人带错。论文因此要求用 human-in-the-loop 的复合指标评估委派系统，而不能只用历史人工标签估计效果。
- bounds [Twilight Factory 设计主张](https://www.oneusefulthing.org/p/agency-and-agents) — 文章提出 facilitator 的四类求助理由，但没有生产级的升级召回率、专家负载、消息设计或长期漂移数据；它是问题入口，不是该组织模式有效性的证明。

### Reasoning

1. 把人叫进来不是一个无成本的安全阀，而是一个二阶判断：facilitator 必须判断 Agent 在当前 case 上是否不如某个人类，并且必须知道该人类拥有哪些自己看不到的现场信息。
2. 这使主动升级与 `EX-001` / `EX-002` 形成嵌套关系：验证器独立性减少共同盲区，证据覆盖保证关键状态进入判定，但二者都不能自动回答“谁在这个 case 上更有优势”。人类隐藏信息构成路由器的观测边界。
3. 路由也不是中性的传输动作。传给人的内容（只说已升级，还是同时展示模型结论）会改变人的注意力、信任和最终判断；因此 facilitator 既选择是否升级，也间接改变被升级者的行为。升级过少会漏掉未知风险，升级过多则把专家时间变成拥堵与审批疲劳。

### 新问题

**EX-003：Facilitator agent 能否在缺少人类隐藏信息的条件下校准“何时升级、升级给谁、给什么上下文”，而不制造新的监督盲区？**

当前判断：这是一个新的选择性委派缺口，而不是对 `EX-001` 或 `EX-002` 的改名。现有一手研究分别指出 rejector 的不可约风险、按类别误校准和消息 framing 对人类表现的影响；但尚无把这些因素放在长程 Agent 主动升级中的部署级纵向验证，故保持 synthesized。

### 证伪方向

- 在同一任务、同一 Agent 和同一专家池上，仅使用可观测 trace 的路由器在分布漂移、专家能力差异和人类负载变化下，能够与拥有一个关键 human-only feature 的路由器或 oracle 路由保持相同的风险加权漏升级率、误升级率和校准；这会削弱“隐藏信息造成不可约路由盲区”的判断。
- 在固定升级预算下，改变 deferral status / model prediction 的消息 framing，不会改变专家或普通人的正确率、拒答率、过度依赖和处理时间；这会削弱“路由结果会反过来改变人类行为”的判断。
- 一个长程生产系统能在模型/任务分布变化后持续报告稳定的 risk-weighted recall、专家负载、false escalation 与 human calibration，并且其 facilitator 的错误可以由独立审计器捕获；这会削弱“主动升级只是把治理问题上移”的判断。

### Source 需求

| 优先级 | 目标 | 当前缺口 | 触发行动 |
|---|---|---|---|
| P0 | Rejector 的校准与隐藏特征 | arXiv 2606.10906 已核读，未进入 raw/source；需提取委派定理、human-only feature、校准粒度和 excess risk 条件 | clip+compile → EX-003 |
| P0 | 选择性预测的按类校准 | PMLR 333 已核读，未进入 raw/source；需提取 per-class calibration、deferral 曲线、expert load 和分布边界 | clip+compile → EX-003 |

| P1 | 主动升级的部署级长程案例 | 缺 facilitator/triage agent 同时报告漏升级、误升级、专家负载、上下文传递和漂移复核的公开纵向数据 | new-source → EX-003 |

### 下一步目标建议

下一轮先 clip+compile `2606.10906`，再用同一字段表接上 PMLR 333 与 `2112.06751`：路由器可见特征、人类隐藏特征、校准对象、升级预算、消息内容、专家负载、风险加权漏报和分布漂移。若只能取得离线分类结果而没有主动升级或人类交互数据，EX-003 继续保持开放，不把 selective prediction 的单任务结果升级为 Twilight Factory 的生产结论。

### 最小实验

在一个已有的人机协作任务上固定 Agent、任务样本、专家池与升级预算，比较两种路由器：

1. 仅看 Agent trace、模型信号和环境状态的 observable-only facilitator；
2. 额外看到一个事先声明的 human-only context 的 facilitator/oracle。

在两种路由器下随机化人类收到的上下文：只告知“系统请求你介入”，或同时展示模型预测。预先记录风险加权 FNR/FPR、专家负载、处理时间、人的最终正确率、拒答率与过度依赖。再在一个已声明的任务分布变化后重复一次：若 human-only context 只改善路由而消息只改变人的行为，说明两条机制有独立增量；若差异消失，收窄 EX-003。当前这是实验设计，不是 evidence。

### Result

- Delta: new_gap
- Conclusion: 新近的 Twilight Factory 设想把“人类介入”推进成一个可检验的路由问题。校准理论、选择性预测实证和人类交互实验共同提示：facilitator 不仅要识别 Agent 何时不如人，还要在不可见的人类信息、误校准和消息效应下管理专家容量；但现有证据来自理论、特定临床任务和离线/短期人类实验，尚未证明长程 Agent 的部署结果。新增 `EX-003`，不新增稳定页面，也不把未剪藏网页写成仓库 Evidence。
- Next: clip+compile `2606.10906`、PMLR 333 与 `2112.06751`，建立主动升级的路由—消息—负载字段矩阵；在取得部署级纵向材料前保持问题开放。

## Explore [2026-08-31T13:03:27] · 真值参考的完整性与锚定效应

- Mode: open exploration
- Trigger: `EX-001` 已把生成者/验证者的目标、证据、执行、时间耦合拆开，`EX-002` 又把证据取得、状态/过程验证和证据解释从模型独立性中分离；但两者都暂时把 reference/ground truth 当作已经正确且语义充分的外部锚点。本轮检查这个前提是否本身构成独立研究缺口。
- Evidence posture: 下列新增网页均为已核读、尚未剪藏的外部一手材料；“reference integrity 是独立门”及其维度、因果关系和实验设计均为 synthesized，不升级稳定 Entity/Topic，也不把网页直接写入稳定 Evidence。

### Evidence

- supports [AgentJudgeBench: A Multi-Difficulty Benchmark for Evaluating LLM Judges on Agentic Tool-Calling](https://arxiv.org/abs/2608.26623) — 一手预印本在 3,808 条记录、六种 DAG 拓扑、五个生成器和六个裁判上，把有无 ground truth 作为配对条件。困难样本中，GPT-5.4 与 Gemini-2.5-Pro 看到 reference 后的 alignment 反而分别下降 1.5 和 3.9 个百分点；附录案例把机制定位为裁判锚定参考顺序，忽略完整性或依赖关系。更关键的是，corrupted-GT 对照中 Gemini 看到不同记录的 reference 仍接近标准 GT 结果，而 QwQ 更接近无 GT 结果，说明“是否出现 reference”与“reference 内容是否正确”是两个变量。
- bounds [AgentJudgeBench 的 programmatic reference 与 human validation](https://arxiv.org/html/2608.26623) — 该研究用确定性程序裁判作为大规模 reference，并以 120 条困难记录的人类复核校验；总体 metric-level agreement 为 92.7%，但 parameter structure 只有 82.5%，且每条记录只有一名标注者。按人类修正后的结果，QwQ-32B 从 programmatic 排名第一降到第四，GPT-OSS-120B 成为最接近人类的裁判。它支持 reference 完整性的重要性，同时也表明“程序可复现”不等于“语义真值已被充分确证”，且该结果主要来自合成的工具调用 DAG。
- supports [OpenAI：Separating signal from noise in coding evaluations](https://openai.com/index/separating-signal-from-noise-coding-evaluations/) — OpenAI 对 SWE-Bench Pro 中 286 个可疑任务做 agent-assisted audit，并让五名工程师先基于题面、测试和 gold patch 独立判断，再参考管线分析；人类把 low-coverage tests 选为主要问题的比例为 9.4%，高于 agent 管线的 4.1%，并展示了隐藏测试与题面一字符不一致却导致正确实现失败的案例。该材料把测试、题面和 gold patch 都置于“需要被审计的测量装置”一侧，而不是默认真值。
- supports [OpenAI：Introducing SWE-bench Verified](https://openai.com/index/introducing-swe-bench-verified/) — OpenAI 让 93 名 Python 开发者对 1,699 个样本做三次独立标注，因题面含糊、测试可能拒绝合理解或其他问题过滤掉 68.3% 样本，并把规格审查、测试有效性和环境可运行性都纳入 benchmark 构建。它提供了“先验证 oracle/测量装置，再用它评估 Agent”的工程对照，但人工筛选仍不能保证测试覆盖所有语义正确解。
- bounds [Are “Solved Issues” in SWE-bench Really Solved Correctly?](https://arxiv.org/abs/2503.15223) — ICSE 2026 论文在 SWE-bench Verified 上发现 7.8% 的通过测试补丁仍未通过完整开发者测试，29.6% 的 plausible patches 与开发者 oracle patch 产生行为差异，其中经人工检查 28.6% 确认错误；作者同时强调 developer patch 也不是唯一正确实现。它把“可执行检查通过”“行为等价”和“真实目标正确”分成三个层次，支持 oracle-side validity 不能被单一 pass/fail 代理。
- supports [ELT-Bench-Verified](https://arxiv.org/abs/2603.29399) — 一手论文复查 100 个 ELT 任务后，在 81 个出现 transformation mismatch 的任务中发现 82.7% 至少包含一个 benchmark-attributable error；30 个 ground-truth calculation error 列的独立专家平均两两 agreement 仅 57.8%。修正评测脚本并移除不可靠 ground truth 后，在同一 agent/model 上 transformation success rate 从 22.66% 升至 32.51%。这说明 reference 语义错误或评测脚本错误可以改变能力排序，且不是换一个更异质的 judge 就能自动消除。
- bounds [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) — 官方方法说明指出，研究型 Agent 的专家会对“是否全面”发生分歧，reference content 会持续变化，长开放式输出也会扩大错误空间，因此要组合 groundedness、coverage、source quality 和 human calibration。它支持 reference 不是静态单点，但属于方法论说明，未提供 reference 替换对 Agent 结果的受控因果实验。

### Reasoning

1. `EX-001` 的 target independence 主要问“生成者和验证者是否共享目标/激励”；`EX-002` 问“关键状态和过程证据是否进入判定”。两者都不能单独回答“判定目标本身是否由正确、完整、语义等价且版本相符的 reference 定义”，也不能回答 reference 被展示时是否改变裁判行为。
2. 本轮暂把 reference integrity（更窄地说是 oracle-side validity）拆成四个可测维度：**来源**（谁生成/维护真值）、**语义**（是否覆盖真实目标及等价路径）、**版本**（题面、测试、reference 是否同步）、**接口**（reference 是中性证据还是强锚点呈现）。前两轮的模型独立性与证据覆盖分别仍然必要，但不能代理这四个维度。
3. AgentJudgeBench 的 corrupted-GT 对照和 OpenAI/ELT-Bench 的 benchmark audit 共同提示两种不同失效：reference 正确但呈现方式诱发锚定；reference 或测试本身错误，制造假阴性。前者接近 judge interface，后者接近目标/测量装置完整性，不能只归入“裁判模型不够异质”。
4. 证据仍不足以宣布这是普遍的第三道门：来源跨越合成工具调用、代码 benchmark、数据工程 benchmark 和研究型 Agent，任务定义与 reference 形式并不相同；尤其 AgentJudgeBench 的 programmatic reference 仍有单标注者和语义等价争议。相反，canonical invariant、可重放账本或形式化 kernel 可能已经提供不依赖人类 oracle 的外部状态；开放式创作也可能没有单一真值。因此本轮只建立候选，不把“最弱轴”或必要性写成定理。

### 新问题

**EX-004：在验证器模型/目标独立性与证据覆盖之外，reference integrity（真值来源、语义等价、版本同步与呈现方式）是否构成 Agent 验证的独立必要门？**

当前判断：最新材料支持把它作为独立候选，而不是简单改名；但如果后续受控实验发现所有残余错误都能由 `EX-001` 的目标耦合或 `EX-002` 的证据缺失解释，则应把 `EX-004` 合并回已有轴，不保留第三门。

### 证伪方向

- 在同一任务、同一生成器输出、同一裁判和同一证据可见性下，随机替换“无 reference / 正确 reference / 语义等价但结构不同的 reference / 跨记录错误 reference”；若裁判的 false accept、false reject、校准和排序对 reference 内容与呈现方式均不敏感，或差异完全由证据覆盖解释，则削弱独立门判断。
- 对同一 benchmark 先做独立人类复核，再修正题面、测试和 ground truth；若 reference 修正既不改变 Agent 排名，也不改变失败归因，说明当前观察主要是局部 benchmark bug，而非可迁移的 reference-integrity 机制。
- 在 reference 版本、题面和测试发生可追溯变更的生产评测中，若经过独立校准仍能稳定保持风险加权 FPR/FNR、语义等价路径通过率和模型排序，且不存在 corrupted-reference 锚定，则应收窄为特定裁判的 prompt/interface 问题；若 canonical invariant、可重放账本或形式化 kernel 能在同样控制下保持外部一致性，也构成对“人类/外部 oracle 必须独立”的边界反例。

## Explore [2026-08-31T13:21:31] · EX-004 补充：目标可辨识性与来源谱系

- Mode: open exploration follow-up
- Trigger: 两组一手来源侦察把“reference integrity”进一步拆成上游 oracle/source-lineage 问题：目标是否可从 Agent 可见数据恢复、来源是否被污染、expected action/规格是否忠实代表任务，以及这些关系能否被版本化回链。
- Evidence posture: 下列材料均已联网核读；它们用于收窄已有 `EX-004`，不新增第五个模型独立性轴，不升级稳定 Entity/Topic，也不把网页直接写成稳定 Evidence。

### Evidence

- supports [Agentic Benchmark Checklist](https://arxiv.org/html/2507.02825v5) — 该框架把 agentic benchmark 的有效性拆成 task validity 与 outcome validity，并要求隔离 ground truth、冻结环境、审查 ground-truth annotation/task setup、允许语义等价表达和控制污染；其跨 benchmark 审查显示任务设定或 reward design 的缺陷可显著高估或低估性能。它把“目标/任务到结果的映射”置于 verifier 之前，但本身是 checklist 与审计框架，不是 oracle lineage 的受控因果实验。
- supports [GeneBench 技术报告](https://cdn.openai.com/pdf/6dc7175d-d9e7-4b8d-96b8-48fe5798cd5b/oai_genebench_benchmark.pdf) — OpenAI 将 graded target 限定为能从 Agent 可见数据恢复的量，而不是不可恢复的隐藏数据生成参数；任务还要经过 target identifiability、科学有效性、prompt-grader mismatch、泄漏与 trace audit 检查。它把“目标可辨识”从“答案是否通过”中分离出来，但证据仍主要来自构造型科学 benchmark。
- supports [AcquaBench: Success Provenance](https://arxiv.org/abs/2607.24054) — 在同一任务与来源暴露结构下配对 CLEAN、提供正确目标的 GOLD、以及替换为错误值的 SHAM；D0 中 GOLD 比 SHAM 高 19.1–25.9 个百分点，说明成功不仅与“看见了某种来源”有关，还与来源内容是否正确有关。该研究主要覆盖问答 benchmark，尚不能单独证明现实世界 target 的权威性。
- supports [OpenAI：SWE-bench Verified 复审](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/) — OpenAI 对 138 个模型长期难解任务做审计，至少 59.4% 存在测试设计或问题描述的实质问题；材料还记录了公共题面、代码库和 gold patch 导致的污染风险。它强化了“测试/规格/gold 不是天然真值”的判断，但测试覆盖与训练污染分别和 `EX-002`、`EX-001` 有重叠。
- supports [tau3 task fixes](https://taubench.com/blog/tau3-task-fixes.html) — 官方修复了 50 多个 airline/retail 任务，包括错误 expected action、歧义指令、不可行约束和缺失 fallback；修复后 airline 的 pass^1 按模型提高 14–20 个百分点。这里分数变化直接来自目标/约束修复，而不是换 verifier；但 tau-bench 是合成环境，不能直接外推为生产结论。
- bounds [Search-Time Contamination](https://arxiv.org/abs/2606.05241) — 深度研究 Agent 在公开搜索中可能取得 benchmark metadata、题面上下文甚至答案，六个公开 benchmark 上报告最高约 4% 的性能膨胀。它说明完整 search trace 仍不保证目标来源独立，但污染机制与 `EX-001` 的证据/时间耦合高度相邻。

### Reasoning

1. 本轮不再把 `EX-004` 泛化成“所有 reference 都要由第三方提供”，而收窄为 **oracle/source-lineage gate**：目标必须可辨识、语义上代表外部任务、来源不被评测循环污染，并能回链到版本化的 spec、policy、真实状态或授权裁决。
2. 新增证据把失败位置向上游移动：即使 Agent trace 完整、verifier 独立且执行状态可见，错误 expected action、不可恢复的隐藏参数、题面/测试错配或 SHAM target 仍会使 verdict 失去外部正确性解释力。
3. 这仍不是第五个“模型独立性轴”。目标泄漏和 search-time contamination 可归入 `EX-001` 的耦合；测试覆盖、状态可见性和 outcome parsing 与 `EX-002` 相邻。真正的新增量是目标 artifact 本身的有效性、来源谱系和语义回链。
4. 反例边界更清楚：canonical post-state、可重放账本或形式化 kernel 可以充当外部 oracle，不需要人类金标准；开放式创作/偏好任务也可能只有版本化 rubric 与多评审校准，而没有唯一答案。新门要求的是可审计、可重算或可授权的目标来源，不是特定形式的人工 gold。
