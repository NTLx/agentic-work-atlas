- Mode: open exploration

- Trigger: 复核 `EX-006` 是否已有在同一任务/可回放轨迹中，对照 context/memory carrier 与 signed/provenance-bound control state，并跨越 preflight、外部效果与 recovery 的一手证据。
- Capability: `research`（后台代理 + 主代理核验）；Skill 输出只作 reasoning，论文、作者代码和官方规范直接报告的实验条件与指标单独保留为 evidence。
- Evidence posture: ControlCapsule/Governance Decay 提供状态衰减与 replay/preflight 对照；SMSR 提供 HMAC 写入来源绑定；OAP/FORGE 提供执行前阻断；MemSecBench/ACRFence 补充生命周期、外部化后果与重复副作用。尚无同一轨迹的 carrier × enforcement × receipt/post-state × recovery 联合证据。

### Result

- Delta: refined
- Conclusion: `EX-006` 不与其他候选合并，也不新增 EX。当前应把问题收窄为 `carrier integrity/survival × authority binding × deterministic enforcement × external effect receipt × recovery semantics`：控制状态衰减、来源绑定、动作前阻断和已提交副作用恢复是不同门，但尚不能推出外部签名控制状态相对 `exact replay + preflight` 的普遍必要性或优越性。
- New question: 在固定 trace、action-surface、verdict、模型和工具模拟器下，carrier 的 authenticity/binding 是否仍会留下 deterministic action monitor 无法吸收的 effect 残差？
- Falsification: 若 exact replay + deterministic preflight 与 signed OOB/passport 在 post-state、receipt 和 recovery 上等效，OOB 只是实现选项；若 HMAC/OAP 只改变 memory admission 或 verdict 而不改变实际副作用和 unknown-commit，来源绑定不能单独解释动作安全；若差异只在 memory persistence，则并回 CR-002。
- Source need: 优先完成 ControlCapsule、Governance Decay、SMSR、MemSecBench、OAP、FORGE、ACRFence 的 clip+compile；继续寻找含 `issuer/version/binding → decision manifest → preflight → action receipt → canonical post-state → recovery` 的生产级或可回放 trace，不再累积只有架构主张的材料。
- Next goal: 用统一字段表对齐 `carrier → issuer/principal → binding → survival → verdict → preflight → actuation → post-state → recovery`，再运行 carrier × enforcement × fault 的最小实验；不创建稳定 Entity/Topic。
- Minimal experiment: 固定任务、工具 schema、预算和单一不可逆模拟工具，随机化 task-local context、exact replay + preflight、persistent memory、signed OOB/passport 与 model-only/deterministic monitor；注入 compaction、unsigned/authenticated poisoning、authority spoof/revoke、授权超时和 checkpoint restore，记录 unsafe/blocked proposal、receipt、submitted/unknown、canonical post-state、duplicate/rollback 与 MTTR。

- Trigger: 议程中的 `EX-003` 需要区分消息可见性、升级触发/时机、接收面和交接包，避免把设计契约当作交接效果证据。
- Capability: `research`（一手来源核查）；Skill 输出仅作为 reasoning，来源直接报告的实验/方法/生产事实单独标注。
- Evidence posture: 2112.06751 提供固定接收面下的随机消息呈现证据；Alibaba 提供随机部署与升级类型/时机的现场材料，但 timing 不是独立随机处理；Google SRE/AWS 主要提供生产设计与 telemetry 契约；2606.10906 与 PMLR 333 提供校准/选择性预测的机制或任务边界。

### Result

- Delta: refined
- Conclusion: `EX-003` 不与 `EX-002` 合并，也不新增 EX。当前可保留 `calibrated trigger → routable receiver → versioned evidence packet → timely human action → outcome verification` 作为待验证的独立操作链；但 packet completeness、receiver availability 和 escalation timing 尚无同一实验中的正交因果证据。
- New question: 在固定模型、任务、接收面和队列状态下，packet 完整性/版本、deferral message 与早/晚升级是否存在交互；Alibaba 的早接管差异有多少来自 timing 本身而非早期状态或选择机制？
- Falsification: 若固定 receiver 和 trigger 后，packet 消融不改变正确率、补问、延迟或过度依赖，packet 子门应并回 EX-002；若固定 packet 后早/晚升级无结果差异，timing 只保留为场景变量。
- Source need: 优先取得固定接收面下的 packet ablation/factorial 实验，或含 `trigger/type → route/receiver → packet/version → human action → outcome` 的生产 trace；先不继续累积无结果指标的 handoff 最佳实践。
- Minimal experiment: 固定 Agent 输出、receiver/capability、queue state 和任务，随机化最小/完整/版本不匹配 packet、仅 deferral/附模型结论消息、可恢复阈值前后升级，记录送达、首次行动、重问/重做、正确率、最终结果、校准和负载。

- Mode: open exploration
- Detailed research: [[20260907--environment-oracle-provenance--research]]
- Trigger: `EX-004` 的既有材料分别覆盖 reference integrity、success provenance 与固定 trace，但仍缺把 reference truth、environment-state truth、execution/post-state truth 分开核验的统一边界。

- Evidence posture: EnvTrustBench 把 true environment state、outcome oracle 与 trace oracle 分开，在 3,850 次受控运行中记录环境误判；EVMbench 用 deterministic transaction replay 与本地链上验证判定 exploit 结果；OpenAI coding audit 说明错误 prompt/tests/gold patch 会单独污染 execution score。三者都没有同一 trace 的三层 factorial 设计。

### Result

- Delta: refined
- Conclusion: `EX-004` 不与其他候选合并，也不新增 EX。当前应把 reference truth、environment-state truth、execution/post-state truth 作为三个不可互替的测量对象；确定性 post-state oracle 不能自动证明 reference 正确或 success provenance，环境 state oracle 也不能替代 execution receipt。
- New question: 在同一 `trace_hash` 与 `post_state_hash` 下，能否用 `reference_version`、`environment_state_hash`、`provider_receipt` 和独立 verifier 区分真成功、错误 reference 伪成功、未验证环境 claim 导致的路径成功与错误 post-state？
- Falsification: 若固定 external post-state oracle 在 reference 与 evidence-provenance 条件变化时仍唯一恢复能力和归因，则三层可收窄为一个 benchmark-validity gate；若 reference 或 claim 条件仍改变归因/排名，三层需保留。
- Source need: clip+compile EnvTrustBench 与 EVMbench；继续寻找同时含 `reference manifest/version → environment state hash → visible/held-out trace → execution receipt/post-state → cross-verifier` 的联合 benchmark，不再把单独 hidden grader 或多模型比较当作命中。
- Next goal: 建立三层 oracle 字段矩阵，并在固定 trace 的 deterministic tool environment 中做 reference × environment claim × verifier-view 最小交叉；不创建稳定 Entity/Topic。
