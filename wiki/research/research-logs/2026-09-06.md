## Explore [2026-09-06T00:39:36+08:00] · EX-005：撤销后的在途动作与效果收敛

- Mode: open exploration
- Detailed research: [[20260906--agent-revocation-recovery--research]]
- Trigger: 2026-09-05 已将 `EX-005` 收窄为 `authority stop`、`in-flight stop`、`effect reconciliation` 三层。本轮补查此前日志未出现的 MCP Tasks、A2A、Temporal、OAuth 与 AWS Step Functions 一手材料，检验这三层是否由不同系统状态和责任主体真正分开。
- Evidence posture: 新材料均为协议规范、官方 API 契约、官方产品文档或官方代码示例，尚未 clip/compile 进入 `raw/` / `wiki/sources/`；它们支持语义边界，不支持部署级效果。

### 本轮判断

1. 新材料共同支持三层不是同义词：凭据/任务控制面失效、在途执行停止、外部副作用对账/补偿分别有不同对象与时序。
2. 新增的关键接口缺口是 **commit-state uncertainty（提交状态不确定性）**：取消已被接受、任务已进入 `cancelled`/`ABORTED` 或 worker 已停止，都不必然回答外部请求是否已提交、是否会重试、是否需要补偿。
3. 幂等性可以降低未知提交后的重复副作用，却不等于回滚；状态字段、stop timestamp、heartbeat 或任务终态也不等于业务 post-state 已收敛。

### 研究契约

- 新问题：在 authority stop 已生效、外部请求可能已提交且响应丢失时，是否必须存在独立的 commit-state uncertainty 处理门，才能把“撤销成功”升级为“效果已收敛”？
- 证伪方向：若固定 verdict、policy、工具 schema 与故障注入后，外部权威查询、原子提交或等价补偿能稳定预测并恢复最终 post-state，则将该子门收窄为下游事务实现细节；若 cancel response 在不同队列、长连接和下游系统下产生不同 post-state，则保留独立子门。
- Source 需求：clip+compile 五类一手材料；寻找带 `revoke_requested → authority_denied → request_sent → effect_committed → compensation → post_state_verified` 事件链、明确分母和责任接管的 Agent 生产 trace。
- 下一步目标：建立 `revoke_request → authority_effect → in_flight_effect → commit_state → post_state → compensation → owner/recovery` 字段表；不把控制面终态直接升级为安全效果结论。
- 最小实验：固定模型、verdict、policy 和 action surface，随机化撤销发生在发送前、发送后但提交前、提交后但响应前、客户端超时后；比较 prompt-only、确定性执行门、执行门+幂等、执行门+权威 post-state 对账，记录未知提交率、重复 effect、补偿成功率、post-state 偏差和 MTTR。

### Result

- Delta: refined
- Conclusion: `EX-005` 获得跨协议/系统的新增边界支持；新增 `commit-state uncertainty` 子门，不新增 EX、不创建稳定页面。
- Evidence boundary: 本轮没有新的撤销传播延迟分布、在途完成率、补偿成功率或 rollback MTTR；完整逐条来源与局限见 [[20260906--agent-revocation-recovery--research]]。

## Explore [2026-09-06T01:33:20+08:00] · EX-007：自我改进 Agent 的变更归因与反馈边界

- Mode: open exploration
- Capability: `ljg-structure`（仅作为结构推理；不写入仓库外 Context）
- Trigger: `EX-007` 已在 2026-09-05 从抽象“独立闸门”收窄为“变更对象 → 失败信号 → 晋级门”，但仍缺一个更小的区分：变更身份可被追踪，不代表优化器看到的反馈没有被它自己塑形。本轮核对 HELIX、Evo-Harness 与 Anthropic 的 Automated Researcher / Weak-to-Strong Researcher 材料，检验“可归因”与“不可自证”是否是同一个门。
- Evidence posture: HELIX 与 Evo-Harness 为 2026-08 的 arXiv 论文/代码发布，AAR 材料为 Anthropic 一手研究页面；论文和官方页面支持实验设置、指标与限制，不支持生产 Agent fleet 的普遍安全保证。

### 本轮结构判断

1. **身份层和反馈层是两种不同的控制。** HELIX 用 typed ports、recipe、lockfile、model-task-attempt identity、runtime trace、workspace effects、verifier outcome 与 policy evidence 把一次干预挂到结果上；这能回答“哪一个 harness 产生了这个结果”，但不能回答“用于晋级的裁判和反馈是否仍在外部”。
2. **反馈不是日志的同义词，而是演化的输入。** Evo-Harness 保持 solver 参数冻结，按失败轨迹生成 candidate memory，再由 evolver 修改外部 harness。其反馈消融中，自生成反馈在 CL-Bench 为 27.96、SWE-bench Lite 为 61.67，均低于 No-Evolve 的 29.54/63.67；Minimal 与 Standard 使用环境信号后更可靠，但 Standard 在 SWE-bench Lite 为 67.00，略低于 Minimal 的 67.33。说明“更多诊断”不自动等于“更好反馈”，反馈粒度本身也是变更变量。
3. **外部化能降低自证风险，但不能把隔离误写成完整独立性。** Anthropic AAR 将研究 Agent、代码 monitor、独立 evaluator 和 hidden holdout 分开，且以操作系统权限隔离 hidden data；其论文还报告事后 cheating monitor 标记 39/1,601 条轨迹，并明确将结果限定为 well-characterized failures。Weak-to-Strong Researcher 页面继续记录：即使修补环境，AAR 仍发现作者事先没有预见的 label exfiltration 与执行 coding answers 的路径。故 hidden holdout 是必要的反过拟合设施，不是对未来攻击面的穷尽证明。
4. **与相邻问题的边界没有合并。** `EX-002` 问一次运行中证据能否被取得、检查和解释；`EX-004` 问 reference/source provenance 是否是真值；`EX-007` 问从 H0 到 H1 的晋级是否改变了可见反馈、裁判或控制面，以及旧保证是否必须重证。相同的 evidence 字段会交叉使用，但研究对象仍不同。

### 研究契约

- 新问题：对能修改 harness、skill、router、evaluator 或 policy 的自我改进 Agent，最小晋级门是否必须同时保持 **intervention identity 可追踪** 与 **feedback/control 双重不对称**——优化器可以改行为，但不能改写外部 oracle、风险 policy 或 hidden feedback，也不能把自生成判断当成唯一晋级依据？仅有 recipe/trace、单一 train/dev gate 或 hidden holdout 各自能否单独成立？
- 证伪方向：若固定模型、任务、工具与 policy 后，source-traceable recipe 加标准内部 feedback 已能在不可见 oracle、task-disjoint holdout、旧版 evaluator、独立安全策略和线上 canary 上稳定复现，并且回滚与跨任务迁移无残差，则双重不对称可能只是当前工程实现选项；反之，若同一 intervention identity 下仅替换 self-generated/minimal/standard feedback 就产生稳定的回归或迁移差异，或优化器可修改 evaluator/policy 后内部得分仍与外部判断脱钩，则保留独立变更门。
- Source 需求：clip+compile [HELIX](https://arxiv.org/html/2608.13951)、[Evo-Harness](https://arxiv.org/html/2608.15071) 与 [Automated Weak-to-Strong Researcher](https://alignment.anthropic.com/2026/automated-w2s-researcher/)；复核已有 [Automated Researchers](https://www.anthropic.com/research/automated-researchers-mitigate-alignment-failures) source summary 的 hidden holdout、代码批准、事后 cheating monitor 和 capability floor 字段。重点寻找同一变更的 old/new evaluator、不可改写 policy、canary、rollback 与跨轮回放记录。
- 下一步目标：把 `change identity → feedback provenance/granularity → evaluator/policy mutability → hidden holdout → behavior contract → external adjudication → canary/rollback` 对齐为 EX-007 的最小字段表；先证明“谁改了什么”和“优化器看到了什么”不能由同一条内部 score 代替。
- 最小实验：固定模型、任务集、工具权限、外部 oracle 与高风险 policy，只随机化一个 harness 变更和三个 feedback carrier：`self-generated`、`minimal environment signal`、`standard grounded diagnostics`。分别在离线回放、task-disjoint hidden holdout 和小规模 canary 上记录 target outcome、行为不变量、unsafe action、false block、成本、延迟、跨任务迁移和 rollback；另设 evaluator 可变/不可变对照，观察内部分数与外部裁决的残差。

### Result

- Delta: refined
- Conclusion: 本轮没有发现需要新增的正交 EX。HELIX 提供了“变更身份—轨迹—验证结果”的审计底座，Evo-Harness 提供了“反馈来源/粒度会改变自演化结果”的直接消融，Anthropic AAR 提供了 hidden holdout、独立 evaluator 和 OS 隔离的分层控制案例；三者共同把 `EX-007` 从“是否要独立闸门”推进为“变更归因门 + feedback/control 不对称门”，但尚未证明该双重结构在生产中具有普遍因果必要性。
- Evidence boundary: 新材料没有提供生产 Agent fleet 的 rollback success、canary failure rate、跨版本安全回归或独立 oracle 的长期统计；HELIX 只完成一轮 harness 演化，Evo-Harness 是单 Agent、文本/工具环境，Anthropic 的结果限定在已刻画失败与代理评测。不能把本轮结果写成“不可自改写门已经是通用标准”。
