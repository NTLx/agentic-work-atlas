## Recompile [2026-08-29T00:01:30] · AI 监督 AI 共模误差下界

- Claim: 即使使用不同模型家族，AI 监督 AI 仍存在不可消除的共模误差下界。
- Gap: Evidence
- Action: evidence_search

### Evidence

- supports 外部一手来源 arXiv 2604.07650《How Independent are Large Language Models?》（2026-04）— 对 6 家族 18 个模型的失败流形做统计审计，发现族内与跨族行为纠缠（behavioral entanglement）普遍存在（含跨代际：GPT-5/Claude 4.6/Gemini 3.6 聚类）；纠缠度与 LLM-as-a-judge 过度背书偏误显著相关（Spearman ρ=0.64, p<0.001, GPT-4o-mini 判官；ρ=0.71, p<0.01, Llama3 判官）。核心命题："entangled 模型的共识可能反映相关误差而非独立验证信号"。这为"不同家族仍存在共模误差"提供独立量化实证与机制定位（共享预训练数据、蒸馏谱系、对齐流程、代际设计）。
- bounds 同上来源 — 去纠缠权重重加权（de-entangled verifier reweighting）把 MMLU 验证精度从 majority voting 0.847 提到 0.896（+4.5%）。即共模误差对聚合决策的影响可被测量并部分工程化削减，但模型间的依赖结构本身不可消除，且恰恰因依赖存在才需要持续重加权补偿。

### Reasoning

1. 上一轮（08-24）已用 Anthropic mislabeling 数据得到"异质 judge 残差 1-14%"；当时"共模来源=训练目标/价值观结构性共享"仍属推断。本轮论文用独立统计框架（BEIw/CIG）直接测量跨模型错误相关性，把该推断升级为可检验、可量化的实证——并精确化机制："不同家族"不等于"独立"，共享谱系信号是共模的来源。
2. 边界澄清：'不可消除的下界'应限定在"模型间误差相关性/依赖结构"层。聚合决策层的精度可通过测量纠缠并重加权来提高（+4.5%），并不违反下界命题——因为模型自身的相关错误没有被消除，只是其影响被调权稀释。两种读法下 Claim 的成立域都被该证据加固而非攻破。

### Result

- Delta: strengthened
- Conclusion: 独立实证确认跨模型家族的行为纠缠（共模相关误差）普遍存在且与判官过度背书偏误显著关联，机制被精确定位到共享谱系（预训练重叠/蒸馏/对齐/代际）；'不同家族⇒监督误差独立'的隐含假设被实证证伪。'不可消除'的适用边界同时被澄清：相关度与依赖结构不可消除，但其对聚合决策的影响可被纠缠感知重加权部分削减（+4.5%）。Claim 从"异质残差 1-14%"推断升级为带独立机制实证与量化指标的下界命题。
- Next: clip 并编译 arXiv 2604.07650 进入 raw/，编译通过后评估收敛 LLM-as-a-Judge entity 的"激励共压层未经独立实证"flag；或把 BEIw/CIG 框架应用到 Anthropic mislabeling 异质残差数据做共模残差来源分解

## Recompile [2026-08-29T01:01:23] · Agent Observability 上界

- Claim: Agent observability 的结构层可枚举、行为层只能竞速、意图层不应被当作可直接观测对象。
- Gap: Boundary
- Action: evidence_search

### Evidence
- supports `raw/20260608-connector-observability-directory.md` — 结构性观测面：adoption metrics（活跃用户/工具调用/目录排名）、health signals（错误率/延迟/per-tool 分解）、usage spread，全部为系统发射的可枚举计数；仪表盘只陈述结构性状态，不对连接器的行为质量或用户意图作任何声明。
- supports `raw/20260819-google-ai-evals-inspect-skill.md` — 行为层只能竞速：skill 是否值得使用必须通过 model×skill×sample×epoch eval 矩阵 + baseline 对照 + 采样统计推断（"we are trying to use sampling to characterize the average observable metrics"）；LLM 随机性使单次结果不可直接读，质量只能由统计竞速刻画。
- bounds `raw/20260819-google-ai-evals-inspect-skill.md` — 意图层不可直接观测：skill 激活与否仅以二元 flag 的结构检查确认（Skill Ingestion Check），并明确指出"若未激活，eval 测的是 baseline 模型知识而非 skill 效用"；"agent 实际摄入了 gemini-api 而非 baseline 记忆"以 "This means" 标注为推断；reasoning loops vs 环境噪音靠 transcript 的诊断解释区分，而非读出。

### Reasoning
1. 三层边界由各自可观测数据的句法决定：结构层=系统确定性发射的 event/count（可枚举）；行为层=仅存在于 sampled outcome 上的统计性质（capability/skill 效用），必须在 baseline 对照下竞速；意图层=agent 是否真的激活 skill / 是否在推理，只能从结构 flag 与行为结局的交叉中推断，无法直接观测。
2. 比较暴露门机制：结构层验证是行为层推断有效性的必要门——Google 明确激活检查不过则"skill 提升"结论即失效；而 Connector 仪表盘完全停留在结构层，不做任何行为/意图声明。三层不是并列的观测类别，而是行为推断以通过结构门为前提、意图声明以结构+行为联合推断为前提。

### Result
- Delta: refined
- Conclusion: 两份 raw 为 CR-004 的三层边界提供了具体锚点与门机制：结构层=可枚举计数（连接器仪表盘）、行为层=必须在 baseline 对照下采样竞速的统计推断（Google evals）、意图层=只能经结构 flag+行为结局交叉推断且以激活门通过为必要前提。Claim 从抽象的分层命题细化为一组带有效性前件（gating precondition）的机制描述。
- Next: clip+compile Anthropic 三案，用「结构门失效→行为结论误导」的预测检验其 eval-escape（141k 次自检通过仍逃逸）是否为门机制的失败例（与 CR-006 共享材料）

- supports [Microsoft 官方 Least privilege for AI agents (agentic identities + RBAC)](https://learn.microsoft.com/en-us/security/zero-trust/sfi/least-privilege-for-ai-agents)（一手厂商文档，2026-07-15 更新） — 明示"Without a first-class identity model, explicit scoping, and enforceable authorization checks, agents might accumulate excessive permissions"；将 "Permission creep and excessive aggregate privileges"（为解锁试点授予宽角色、稳定后从不收窄；叠加多个"窄"角色产生过宽聚合权限）与 "Over-broad tool access"（agent 可调用任意工具时单一 prompt injection 即可触发 export/delete/权限变更）列为默认威胁路径；数据最小化被表述为必须由外部 identity+授权体系刻意施加的设计要求，而非 agent 默认属性。
- supports [CSA Research Note: Overprivileged by Design: AI Agents as Cloud Escalation Vectors](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-agent-cloud-privilege-escalation-202604)（行业组织，2026-04） — 把生产 agent 默认权限过宽正式命名 "Overprivileged by Design"，引 HiddenLayer 2026 调查（250 名安全负责人）：约 1/8 AI 泄密与 agentic 系统相关。
- supports EDPB Guidelines 02/2026 on AI and Personal Data（监管规范，via MTM 合规转述；最终版预期 2026 H2 发布） — 明确数据最小化与目的限制适用于 agent 决策链的每一步而非仅人机初始 prompt；CNIL / DSK / Garante 已对商业 agent 部署开展调查，最常见发现是"agent 执行的具体处理无 documented 法律依据"，即跨辖区重复的同类失效。

### Reasoning
1. 反例检索失败本身是发现：以最有利于反例的两类检索词反复搜，最高证据等级返回物（微软官方模式、CSA、EDPB）全部把"最小化"写为必须由外部身份/授权/治理体系施加的设计要求——这与 MosaicLeaks"任务信息密度与泄漏正相关"的机制指向一致，而非出现反例。
2. 新增材料把"跨厂商重复出现"从零散事故案例（Copilot 被 prompt injection 利用、Meta 强收集、Anthropic 93% 审批疲劳）扩展到生产生态的结构性一致观察：微软（agent 身份体系缺失 ⇒ 权限累积）、安全行业（命名 taxonomy：overprivileged by design）、欧盟监管（最小化适用于 agent 决策链每步，多家 DPA 已调查）。这使排除性表述"而非单一厂商实现失误"获得跨厂商、跨辖区的独立一致性支持。
3. 证据等级边界：以上为规范性文件、厂商官方模式与调查转述（中低等级），非一手透明泄密数据，不能构成量化泄漏率证据；"暂未找到部署级反例"经定向检索后成为更可信的负证据，但反例 Gap 仍保持开放（将来若出现带外部审核记录的 agent 长期最小化案例即可 weakened）。

### Result
- Delta: strengthened
- Conclusion: 两轮定向反例检索未能找到"权限相近却长期数据最小化"的部署级 agent；但检索暴露了跨厂商、跨辖区的一致结构性确认——微软官方文档承认 agent 默认积累过度权限、必须由外部身份体系约束；CSA 将其命名为 "Overprivileged by Design"；EDPB 明示数据最小化应约束 agent 决策链每步且多家 DPA 已调查发现同类缺失。Claim 的架构归因与"而非实现失误"的排除性表述获得新的一致性支持并外扩到监管层面；反例（Gap）仍空置。

3. Lean kernel 与 nanoda 的案例把独立性落到实现和时间上：不同实现的检查机制仍有价值，但旧版检查器因版本过期而失去实际保护力。独立实现不是一次配置，而是需要持续更新的运行属性。
4. Anthropic 的 motivated mislabeling 结果显示，跨家族 judge 的错误率可以低于同家族 judge，但同一后果框架、同一研究/训练流程和共享激励仍可能留下共压；“不同家族”只消除了其中一条可能的相关路径。
5. 自动化对齐研究通过 withheld benchmark、Petri 和过程监控扩大了验证边界，但它仍使用预先选择的失败类别和有限代理环境；它把证据隔离做得更强，却没有证明目标、激励和执行结构已经独立。

### 降秩与约束综合

验证器危机的根骨架不是“模型够不够强”，而是生成者和验证者之间有三条可能共享的路径：

1. **目标耦合**：验证者和生成者从同一个成功标准、训练结果或组织奖励中获益，于是验证者有理由把“符合我认可的方向”当成“通过流程的事实”。这条路径解释 co-adaptation 和 motivated mislabeling。
2. **证据耦合**：两者看过同一训练材料、答案、轨迹或污染后的评测环境，于是“共同没看见”会被误当作“彼此印证”。这条路径解释跨家族行为纠缠和 benchmark contamination。
3. **执行耦合**：两者依赖同一实现、harness、解析器、沙箱或旧版本，于是同一个漏洞可以同时穿过生成和检查。版本新鲜度不是第四个根生成器，而是决定执行独立性是否仍然有效的时间约束。

可操作地把独立性写成四轴：

| 轴 | 要隔开的东西 | 现有材料覆盖 | 轴失效时的盲区 |
|---|---|---|---|
| 目标 | 成功标准、奖励、责任归属 | Berkeley；Anthropic mislabeling | 验证者把偏好或组织目标当成事实 |
| 证据 | 训练语料、答案、轨迹、评测环境 | arXiv 2604.07650；withheld benchmark | 共同错误被当成共识 |
| 执行 | 实现、harness、工具链、enforcement point | Lean/nanoda；同 Agent 写实现和测试 | 同一 bug 穿过两道门 |
| 时间 | 版本、补丁、测试轮换和新鲜度 | Lean/nanoda；自动化研究的未见评测 | 旧检查器继续提供已经失效的安全感 |

本轮的候选判据是：**有效保障不是四轴平均，而受最弱轴限制。** 某一轴接近零，并不代表其他轴没有价值；它只意味着系统不能对该轴对应的失败类别作出保障。跨模型家族可以改善证据轴，却不能补上目标耦合；独立实现可以改善执行轴，却不能证明评测集没有被共同污染；未见评测可以改善证据轴，却不能替代当前版本的 enforcement point。

```
生成者与验证者
        |
        +-- 目标耦合 ------> 共享成功标准 / 共压 / co-adapt
        |
        +-- 证据耦合 ------> 共享语料 / 答案 / 轨迹 / 污染
        |
        +-- 执行耦合 ------> 共享实现 / harness / 漏洞
        |                         |
        |                         +-- 时间新鲜度决定保护是否还在
        v
有效保障 = 各轴都能覆盖对应失败类别
```

这不是“多找几个不同模型”的升级版，而是把“独立”从名义属性改成关系属性：问的不是验证者是谁，而是它和生成者在哪些关键路径上没有共享东西。

### 新问题

主问题：**验证器独立性的最小充分条件是什么？** 更具体地说，四轴中任一轴为零时，保障是否必然在对应失败类别上坍塌，还是其他轴可以补偿？

分问题：

- 同一家族、同一实现的验证器，只要拥有真正独立的目标，能否比“跨家族但共享奖励”的验证器更少漏报？
- withheld 或 secret benchmark 能否阻断证据耦合，还是只把污染从答案层推到任务结构层？
- 版本新鲜度是连续的风险曲线，还是存在“旧到某个阈值就等于没有验证”的断点？
- 生成者越能读取公开 bug 报告和验证器规则，所谓实现独立是否会退化成“只对未公开缺陷独立”？

### 证伪方向

- 找到受控研究：只改变模型家族，保持目标、输入证据、实现和版本不变，跨家族验证在多类错误上稳定消除相关漏报。若成立，说明“家族差异只覆盖证据轴”过于保守。
- 找到目标操纵实验：同家族 verifier 在独立奖励/不影响训练结果的条件下，与跨家族 verifier 的错误模式没有显著差异；这会削弱目标耦合是独立根的判断。
- 找到新旧版本对照：在可复现 exploit 上，过期 verifier 与当前 verifier 的检测率和覆盖域没有实际差异；这会把“新鲜度是执行独立性的必要条件”降为局部工程经验。
- 找到单轴失效但完整保障仍成立的案例：验证者与生成者共享目标、证据或实现中的一项，却在针对该失效类别的对抗样本上维持低漏报。需要的是攻击前声明的测试，不是事后挑选成功案例。
