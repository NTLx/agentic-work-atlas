## Explore [2026-09-05T00:44:53] · 自我改进变更的行为契约与独立归因

- Mode: open exploration
- Trigger: 最新编译的 GitHub Copilot 成本优化材料给出了一个此前 `EX-007` 缺少的具体边界案例：prompt 压缩在离线评测中未暴露问题，却在首次线上实验中把独立 Agent 的并行执行改成串行；团队停止实验、补写行为回归评测后才恢复并行。当前问题不是是否要再造一个 EX，而是 `EX-007` 的“独立变更闸门”是否需要拆成不同强度的门。
- Evidence posture: GitHub 成本优化文章已进入本地 `wiki/sources/`，可作为当前 Evidence；GitHub Applied Science、Anthropic 与 Uber 页面为本轮联网核读、尚未剪藏的外部一手材料，只用于导航与 reasoning，不升级稳定 Entity/Topic。

### Evidence

- supports [[20260902-github-ai-coding-cost-efficiency]] — GitHub 把完整任务而非单次 tool call 作为效率单位；其 prompt 压缩实验中，离线评测未发现行为问题，首次线上实验却发现并行 Agent 被序列化。团队据此先停止实验，再增加针对并行行为的回归评测，最终用更短的指令恢复行为；文章还强调同一改动在不同 Copilot workflow 中可能产生相反结果。
- supports [GitHub: Agent-driven development in Copilot Applied Science](https://github.blog/ai-and-ml/github-copilot/agent-driven-development-in-copilot-applied-science/) — 官方开发记录描述了一个只能由人改动或必须保留的测试空间，把它作为防止 Agent 为适应新范式而改写测试的 contract-like guardrail。这是“行为不变量需要保护边界”的实践线索，但没有给出跨版本回放、回滚成功率或安全收益的量化结果。
- supports [Anthropic: Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps) — Anthropic 将 harness 的每个组件视为关于模型能力边界的假设，并主张逐个移除、逐个检查影响，因为模型能力变化会使原本 load-bearing 的组件过时；其材料同时指出 evaluator 可能自我宽松，需通过调校和外部反馈提高判断质量。该材料支持“harness 变更本身是实验变量”，但不是独立变更闸门的因果证明。
- bounds [Uber: Running a Software Factory Efficiently at Uber Scale](https://www.uber.com/by/en/blog/efficient-software-factory/) — Uber 为隔离优化收益而固定模型，并按真实工作 benchmark、任务完成成本和质量信号（如 revert rate、F1、MTTR）观察 managed agent；这提供了版本归因的工程做法。但公开材料没有给出冻结外部 evaluator/policy、隐藏 holdout、rollback 成功率或独立安全复评，因此不能替代 `EX-007` 要求的控制边界。

### Reasoning

1. `EX-007` 原先把“独立变更闸门”说成一个总条件；本轮证据把它拆成两类失效。第一类是**行为变化未被普通结果门看见**：任务可能仍通过测试，但并行、停止、检索、通知或副作用顺序已经改变。第二类是**提升无法归因**：当 evaluator、目标或 policy 与 harness 一起变化时，内部得分上升可能来自真实能力、评测器变宽、目标变窄或 benchmark 接口适配。
2. 因而暂定两层结构：
   - **行为契约门**：把并行语义、授权前停顿、结果交付、不可重复副作用等需要保持的不变量写成受保护回归测试；它首先回答“这次变更有没有改写系统行为”。
   - **独立归因/安全门**：当变更触及 evaluator、reference、policy 或高风险执行边界时，用冻结的外部 oracle、隐藏任务、只读 policy 和可回放 manifest 检查旧保证是否仍成立；它回答“分数/成本变化是否可解释、是否有安全回归”。
3. 这是对原命题的边界收窄，不是把所有 harness 维护都升级为强人工审批。只改格式且不改语义的优化，可能只需要行为契约与工作流本地复评；但 prompt、orchestration、router、evaluator 或 policy 的改变，不能由单一内部 acceptance gate 自证。
4. GitHub 的单案不能证明“线上一定比离线更真”，只能说明离线 gate 对某类行为回归存在漏检可能。Anthropic 与 Uber 的材料共同支持更窄的工作假设：变更必须按实际 workflow、模型版本和控制面记录来评估；它们尚未提供长期、跨组织、可复现的独立安全证据。

### 新问题

**`EX-007`（refined）：当优化器只修改行为组件而 evaluator/policy 冻结时，受保护行为契约加工作流本地在线复评，是否足以承担变更门；一旦 evaluator、reference 或 policy 也可被优化器修改，独立且不可自改写的归因/安全门是否不可替代？**

当前判断：`EX-007` 仍保持 `synthesized` 和开放状态。最新材料使其从“是否需要一个抽象的独立闸门”收窄为“哪些组件变更需要哪种不可自证的门”，但还没有同一任务上的分层对照。

### 证伪方向

- 在固定模型、任务、工具权限、oracle 和 policy 后，仅修改 prompt/harness；若普通 outcome gate 加工作流本地在线复评已稳定捕获并行、检索、停止和副作用顺序的变化，且受保护测试区不再提供额外召回，则削弱行为契约门的独立必要性。
- 若允许 evaluator 或 policy 与 harness 共变，内部 acceptance gate 的提升仍能在冻结外部 oracle、隐藏 holdout 和独立安全策略上稳定复现，且跨任务迁移、回放和 rollback 不变，则削弱独立归因/安全门的必要性。
- 反过来，若优化版本通过普通质量门和本地线上指标，却在冻结 policy 的隐藏任务上出现 unsafe action、false block 或意图保持下降，则证明“成本/质量无回归”不能替代独立安全复评；这会强化 `EX-007`，但仍需多个任务或组织案例排除单一 harness 事故。
- 若所有版本残差最终都能由 `EX-004` 的 reference/source-lineage 失效或 `EX-006` 的 policy-carriage 失效解释，并在冻结 target/policy 后消失，则将 `EX-007` 并回已有候选。

### 最小实验

在一个可回放、可控副作用的多 Agent 编程任务上固定模型、任务集、工具权限、evaluator 和高风险 policy，只做一次 prompt 或 orchestration 优化，比较旧版 `H0` 与新版 `H1`：

1. 先跑普通 outcome gate（任务成功/测试通过、成本、轮次）。
2. 再跑不可由优化器改写的行为契约集：独立任务是否保持并行、后台结果是否避免重复 retrieval、未授权动作是否在边界前停止、失败后是否可回放。

## Recompile [2026-09-05T00:56:27] · AI 监督 AI 共模误差下界

- Claim: 即使使用不同模型家族，AI 监督 AI 仍存在不可消除的共模误差下界。
- Gap: Boundary
- Action: reasoning_operator
- Skill: `ljg-think-recompile` (`.agents/skills/ljg-think-recompile/SKILL.md`)

### Evidence

- supports [Apple Machine Learning Research：Nine Judges, Two Effective Votes](https://machinelearning.apple.com/research/correlated-llm-evaluation-panels) — 既有一手研究在 7 个模型家族的 9 个 judge 上观察到约 2.18 个有效独立投票，面板准确率低于独立投票基线 8–22 个百分点，且结果对任务、提示、温度和 chain-of-thought 变体保持稳定。
- bounds [arXiv 2607.10139v3《LLMs as a Jury》](https://arxiv.org/abs/2607.10139) — 既有一手研究的跨家族 verifier panel 在数学任务的 shared-error floor 接近 0，在 GPQA 为 0.030、MMLU-Pro 为 0.143；更换 generator 后仍复现，材料对象是特定 consensus/verifier panel 与 benchmark。

### Reasoning

- shared-error floor 是由任务错误结构、panel 组成和共同可见证据条件化的残余错误，不是跨所有监督系统的固定常数；跨家族只削弱部分相关性，不等于条件独立。
- 数学任务的近零结果限定了适用边界：可执行或可核查任务可能把该面板的残余压到很低，但不反驳开放式科学/知识任务中的非零 floor。
- 现有材料没有测试外部 checker、人类 adjudicator 或其他独立观测路径能否打破该相关性，因而不能把面板结果外推为所有 AI 监督形态的下界。

### Result

- Delta: no_delta
- Conclusion: 本轮只用既有证据复核 CR-003，未发现超出此前“任务与 verifier 条件”边界的新事实或实质新区分。Claim 继续保持条件化理解，不应普遍化为所有 AI 监督形式均有同样的不可消除下界。

## Explore [2026-09-05T01:49:04] · 验证器的 reference integrity 与 success provenance

- Mode: open exploration
- Trigger: `EX-004` 已有多条待剪藏的一手材料，但“reference 是否正确”与“成功是否由评测中获得的信息造成”仍被同一个 oracle/source-lineage 标签笼统承载。本轮用 AgentJudgeBench 的 corrupted-GT 控制和 AcquaBench 的 CLEAN/GOLD/SHAM 干预，检查这两个问题能否继续并为一个门，还是需要分成两个可独立验证的子门。
- Evidence posture: 以下均为本轮联网核读的一手论文或官方材料，尚未进入 `raw/` / `wiki/sources/`；只进入本日志和 Source 需求队列，不升级稳定知识页。

### Evidence

- supports [AgentJudgeBench 一手论文](https://arxiv.org/html/2608.26623) — 论文把同一生成器输出分别交给 programmatic reference 与 LLM judge，并在 with-GT / without-GT 条件下比较；GT trace 经过 JSON schema、参数类型和 trace consistency 的程序检查，另有 120 条 hard 记录的单标注人类校验。作者同时明确指出：120 条样本只有每条一个标注者，不能给出人类标签自身的 inter-annotator agreement。
- supports [AgentJudgeBench 的 corrupted-GT 控制](https://arxiv.org/html/2608.26623) — C3 用同拓扑另一条记录的错误 GT 替换正确 reference；Gemini-2.5-Pro 在 corrupted-GT 下与标准 GT 几乎一致，QwQ-32B 则接近 without-GT，提供了“锚定 reference 的存在/格式”与“检查 reference 内容”之间的区分。论文还记录了 fan-in 中结构上可交换的 sibling calls：程序化 scorer 以位置精确匹配，judge 认为功能上合理，暴露 structural-vs-semantic 的 oracle 边界。
- supports [AcquaBench 一手论文](https://arxiv.org/html/2607.24054) — 在同 qid、模型、action channel、reference target 与 scorer 下，CLEAN 只保留授权信息，GOLD 注入正确 target，SHAM 保留来源结构和暴露机会但替换为匹配的错误值。D0 中三种模型的 GOLD–SHAM 均为正（+19.1 至 +25.9 个百分点）；D2 把充分信息分散到两个来源后，GOLD–SHAM 仍为正，但单源 coloc AUROC 降到 0.376 / 0.142，说明成功的目标值依赖与单源可见性不是同一个对象。
- bounds [AcquaBench 研究边界](https://arxiv.org/html/2607.24054) — 这是 HotpotQA 单一 benchmark family 上的冻结、可构造干预，不是自然污染率估计；四种 action surface 是同一干预的标准化接口，不是四个独立部署复制。它固定 reference target，因而不能单独验证静态 oracle 是否正确；AgentJudgeBench 也主要验证结构化 tool-calling 的 programmatic reference，不能外推到开放式 judge 或生产 trace。

### Reasoning

1. `EX-004` 不应再把所有“来源”当成一种风险。至少要区分：
   - **静态 reference integrity**：目标是否可辨识，reference 是否正确、语义等价、版本同步，程序化 scorer 是否把结构偏好误当成任务真值；
   - **动态 success provenance**：在 reference 固定时，分数是否跟随评测期间获得的正确目标信息，而不是只跟随“见过某个来源”或 outcome 结果。
2. AgentJudgeBench 的 C3 直接操纵 reference 内容，因此支持静态门具有独立可观测变量；它也显示“给 reference”并不等于“增加真值”，因为 judge 可能只对 reference block 锚定。AcquaBench 则操纵 agent 的信息状态，说明静态 reference 正确仍不足以解释 score 的因果来源。
3. 两者暂时仍留在 `EX-004`，因为共同问题是“评测结果究竟回链到哪个权威对象”：前者回链到任务/裁判的 oracle，后者回链到轨迹中的信息状态。现在新建候选会重复 oracle/source-lineage 主线；下一轮若控制实验显示动态 provenance 的残差在 reference 与 evidence coverage 固定后仍稳定存在，再考虑把它升级为独立候选。
4. 本轮不把 AgentJudgeBench 的 92.7% 人类一致率当作强真值证明：该研究明确只有单一标注者，且 programmatic scorer 对 parameter structure 的人类一致率降至 82.5%。同样，不把 AcquaBench 的四个 action surface 当作独立重复样本；两篇论文的边界声明都要求保留这种克制。

### 新问题

**`EX-004`（refined）：在固定生成器输出、任务、工具权限与 evidence coverage 后，reference 的正确性/语义等价/版本绑定是否仍独立影响 judge 判定；在 reference 固定后，评测期信息状态的 success provenance 是否还会独立改变结果解释？**

当前判断：`EX-004` 仍为 `refined`、开放状态，但内部至少有“静态 oracle integrity”和“动态 success provenance”两个子门；尚无同一任务上的交叉操纵，因此不把它们误写成两个已证实的必要条件。

### 证伪方向

- 若在同一 trace 上将 reference 随机化为无 reference、正确 reference、语义等价 reference 和错误 reference 后，judge 的错误、校准与排序对 reference 内容不敏感，则静态子门可并回 `EX-001/EX-002` 的目标或证据覆盖问题。
- 若在固定 reference、scorer、模型与任务后，CLEAN/GOLD/SHAM 的 score 与 provenance 指标无稳定差异，或差异完全被 exposure detection 解释，则动态子门无需独立保留。
- 若两类差异只在 AgentJudgeBench 的 synthetic DAG 或 AcquaBench 的 HotpotQA 构造中出现，而在真实可回放 agent trace 的语义等价 reference 与多来源信息路径中消失，则收窄为 benchmark-construction artifact。
- 反过来，若 reference 内容效应和 success-provenance 效应在 evidence coverage、模型家族和任务难度固定后仍各自保留，并改变 human adjudication 或模型排序，则 `EX-004` 的 oracle/source-lineage gate 获得独立残差支持。

### 最小实验

在一个可回放的多步 tool-calling 任务上，固定 agent trace、任务、模型、工具权限、scorer 与 evidence coverage，做两层最小干预：

1. 对同一 trace 仅改变 judge 可见的 reference：`none / correct / semantically equivalent / corrupted`，记录 judge verdict、human adjudication、calibration 与排序变化。
2. 对同一 qid 再做 `CLEAN / GOLD / SHAM` 信息状态配对，保留来源结构与暴露机会，记录最终 outcome、信息路径、exposure detector 和 score。
3. 只有当 reference 条件与 information condition 的效应在各自另一维固定后仍存在，才把两个子门视为独立残差；若残差只由 reference 或 exposure 一项解释，则并回已有候选。

### Evidence

- supports [FORGE / Formal Policy Enforcement for Real-World Agentic Systems](https://arxiv.org/html/2602.16708v3) — v3 将模型、工具、消息和人类视为可不可信组件，由部署环境提供 provenance substrate，reference monitor 在每个 action join point 之前作确定性 Allow/Deny。论文报告三组受控结果：prompt-injection 成功率 5/5 降到 0/5、`τ²`-bench 合规率从 58% 提到 98%、MALADE 未授权 FDA 访问从 40 次降到 0；任务正确性保持，代价主要来自被阻断后的重试，端到端延迟约增加 19%–38%。这为“执行边界可独立于模型推理”提供了比单一架构宣言更强的初步支持。

- supports [OAP / Before the Tool Call](https://arxiv.org/html/2603.20953v1) — `before_tool_call` hook 在每次工具调用前验证 signed passport、capability、参数和 policy，返回 `ALLOW / DENY / ESCALATE`；作者报告 1,151 个 session、4,437 次授权决定，以及银行 CTF 中 restrictive policy 的 879 次尝试全部被阻断，云端授权 p50 约 53ms。该材料把“模型已被社会工程说服”与“策略层仍拒绝执行”做了清晰分离。
- bounds [OAP 的实验与实现边界](https://arxiv.org/html/2603.20953v1) — T1/T5 是参与者自选的观察性比较，不是随机对照，只有银行单域；作者明确列出 framework hook、policy engine、签名基础设施为信任假设，`ESCALATE` 在参考实现中尚未完成，逐次允许的调用还可能通过累计效应完成结构化攻击，且授权范围内的意外副作用不在防护范围。作者同时是 OAP 实现公司的创始人，因此结果只作候选机制证据，不作跨域效果估计。

- bounds [Google DeepMind：Securing the future of AI agents](https://deepmind.google/blog/securing-the-future-of-ai-agents/) — 官方 AI Control 路线将 coverage、recall、time-to-response 分开，并明确低风险/可逆动作可异步修复，高风险动作需实时、事前阻断；页面提到已分析百万 coding-agent tasks 并建设 live monitor，但未提供逐案阻断率、撤销延迟或恢复成功率。

1. `FORGE` 与 `OAP` 不是同一实现的重复宣传：一个以 provenance graph + Datalog reference monitor 为核心，一个以 signed passport + synchronous hook 为核心；二者都把“模型提出了什么”与“平台是否放行动作”置于不同的信任边界。结合已有 HF 事故和 Anthropic 只读诊断实践，`detection → verdict → authorization` 的断点现在有了收敛的机制证据。因此，确定性 pre-action enforcement 可以作为 `EX-005` 的独立、可测子问题。
