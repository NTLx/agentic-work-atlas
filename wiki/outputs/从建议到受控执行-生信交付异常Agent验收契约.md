# 从建议到受控执行：生信交付异常 Agent 的验收契约

> 用途：内部 Agent 试点设计与上线决策的可复用模板。以下是通用假设案例，不描述任何实际企业系统、数据、生产权限或已实施项目。本文仅使用既有 Wiki 知识；阈值、阶段和测试均为建议，不是已取得的试验结果。

## 决策问题

生信交付流程发生异常时，是否应允许 Agent 从定位问题、提出处置建议，晋级到自动执行？如何在减少人工重复排查的同时，避免错误交付、重复执行、敏感数据泄露，以及团队逐渐失去独立定位问题的能力？

建议先选一类可隔离、具有可靠状态查询和明确处置责任人的流程异常试点。**先证明这一类动作能够被独立核验、授权和恢复，再扩大委派范围；不以更长的自主运行时间或更高的表面完成率作为晋级条件。**

## 1. 最小工作单元及授权边界

一个工作单元是一条异常事件对应的有界处置，而不是“解决所有交付问题”。例如，假设某计算任务退出失败，Agent 可以查询其状态、读取经允许的诊断信息、按既有规则归类，并形成处置建议；重试、修改参数、数据修订与重新发布则是独立动作。

| 阶段 | 可做 | 暂不允许 | 晋级前置条件 |
|---|---|---|---|
| A · 影子/只读分诊 | 读取最小状态与脱敏日志、定位候选原因、提交证据及建议 | 写入生产任务、修改交付结果、对外发送客户数据 | 任务与权限映射、独立标签、漏报/误报及数据披露验证 |
| B · 计划批准后执行 | 经责任人批准的具体重试或其他已验证可补偿动作 | 扩大作用域、改变审批内容、跳过 QC、自动发布正式交付 | 计划/资源/版本/批准绑定，模型外执行检查，幂等或先核验终态，失败接管 |
| C · 有界自动处置 | 仅对经单独验证的、状态明确且影响有界的动作自动执行 | 未知类别、不可逆/高影响动作、数据或报告发布、权限变更 | 本类动作的负例/故障注入/恢复实测，独立人类签收，持续回归与紧急停止 |

不是所有动作都要晋级至 C。低风险的确定性重试规则若已经足够，直接由现有工作流执行即可，Agent 只处理语义不明确的例外。只读也需要访问和披露限制。Vercel 的计划级授权是可参考的设计样本（[[20261023-vercel-agent-production-safe-access]]），不是生产安全认证或本文试点的实测结果。

## 2. 五个不可互相抵消的验收门

| 验收门 | 必查证据 | 失败处理 |
|---|---|---|
| G1 诊断与评测可信 | 明确任务 ID、输入/运行版本、错误证据、独立 SOP/QC 参照、允许多个有效答案；盲留测试集 | 未知或冲突不自动归因；提交人工判断 |
| G2 权限与数据边界 | 授权主体、资源/动作/版本、实际读取、模型暴露字段、第三方披露、保留/删除策略 | 未授权动作由系统拒绝；泄露或范围不明停止晋级 |
| G3 动作及终态 | 计划 hash/版本、批准与有效期、下游执行检查、幂等标识、外部回执、权威状态、独立 QC | 未知提交状态先对账；不以 Agent 声称、任务退出 0 或单次工具成功作为交付证明 |
| G4 接管与恢复 | 告警实际送达、接收人确认、接手权限、在途动作结局、补偿/恢复结果、再次核验 | 无人接手转备用责任人；不把撤销权限当撤销既有外部效果 |
| G5 人员与运营能力 | 人工基线、含复核/返工的主动工时、独立诊断与接管演练、总周期与质量 | 不以提速抵消独立能力下降；对新手保留实际练习与反馈 |

G1 来自 [[Verifiable-Agent-Engineering]] 与 [[Evaluation-Integrity]] 的结果/执行/评测分离；G2/G3/G4 来自 [[Agent-Data-Minimization]]、[[Agent-Security]] 和 [[Alert-Closed-Loop]] 的授权与效果、告警与责任边界；G5 借用 [[Skill-Atrophy-and-Knowledge-Debt]] 的辅助表现与独立能力区分。五门是本案例的决策组织方式，不是所有 Agent 的通用必要充分条件；门的强度按动作影响分层。

## 3. 最小执行与结算协议

复用现有工作流、工单和权威业务状态，不另建平行事实源，也不要求新增五个微服务。持久事件、审批等待与消息送达可用已有系统实现（[[Organization-as-Agent-Harness]]、[[20261113-anthropic-building-always-on-agents]]）。

1. 接收异常事件，绑定唯一事件、任务与尝试标识；重复通知不产生第二个逻辑处置单。
2. 只读调查：提交当前状态、异常证据位置、规则版本、可能原因、不确定性、建议动作与不做动作的条件。未见证据标为未知。
3. 需要副作用时：按当前计划及目标对象版本批准；等待期间发生状态/权限变化则重新校验。审批不是聊天中的一句同意。
4. 执行前通过模型外策略/资源检查。若下游支持幂等键，绑定同一逻辑动作；否则用权威状态核验与人工处置约束重试，不能承诺 exactly-once。
5. 记录下游回执与权威终态，独立核验关键 QC 与交付条件；分别记录处置完成、待复核、通知送达。自动重跑成功不等于可自动重新交付。
6. 取消时分别核对未来授权、已发在途请求、已提交效果及补偿后的状态。收到告警不等于已经接手。

建议最小关联字段：incident_id、task_id、attempt_id、resource_version、policy_version、proposed_action、approval_ref、action_id / idempotency_key、dispatch_receipt、authoritative_post_state、qc_ref、owner、handoff_ack、recovery_ref。按实际业务系统能力裁剪；日志存引用和必要元数据，不复制敏感原始数据，不保存凭证。授权范围、实际读取、模型披露及留存分别核验。

## 4. 纸面故障演练：重试请求已提交，但响应丢失

假设初始任务 T-01 失败（合成标识）。责任人批准了一次有界重试。执行器向调度系统发出请求后连接超时。Agent 未收到确认，原任务界面仍显示失败，而调度系统可能已建立新的运行尝试。

| 分支 | 预期处理 | 验收依据 |
|---|---|---|
| 权威调度系统确认已建立新尝试 | 关联既有尝试，不再次发出重试；等待状态/QC | 实际尝试 ID、回执或查询证据 |
| 权威系统明确未接收，且动作仍获授权 | 按已验证幂等/重试契约执行 | 同一逻辑动作，权限仍有效 |
| 调度系统不可查或查询结果不确定 | 标记未知提交状态，停止自动重试并交接 | 责任人实际接收及后续对账 |
| 等待过程中批准过期或对象改变 | 原批准不能用于新状态，重新审批/拒绝 | 对象版本、权限与时间戳 |
| 新尝试完成但 QC 不通过 | 不宣布交付完成，不发布报告，升级复核 | 独立 QC 记录与结果版本 |

反例：只看“重试工具成功返回”的系统会把请求、动作、终态混为一谈；只看“旧任务失败”的系统则可能重复提交，造成额外资源消耗或多个输出版本。这个推演说明必须测试何种条件，不证明任一现有系统确实存在此漏洞，也不证明设计已经能防止漏洞。实际实施需在隔离环境注入响应丢失、重复事件、授权过期与 QC 失败并检查真实状态。

## 5. 如何做最小对照试点

以同类、脱敏或合成异常为单位，冻结 SOP、输入和状态版本、任务复杂度及通过条件。基线是现有人工/确定性工作流，不是无工具人类；候选是 A 阶段的 Agent 辅助。先影子评测，再在独立权限和数据条件明确的隔离环境执行 B 的故障测试。由实际领域责任人确定样本构成和可接受风险，不预设当前企业具备某个系统能力。

| 指标 | 口径 |
|---|---|
| 诊断质量 | 可复核的正确归类与证据充分性 / 全部合格事件；另报未知、拒答、严重漏报与误报 |
| 业务结局 | 经权威状态和 QC 验证的结案 / 全部纳入事件；超时、失败、转人工不从分母静默删除 |
| 风险 | 未授权动作、跨资源披露、重复副作用、错误交付等按类别分别记录，禁止用平均得分掩盖 |
| 效率 | 人工主动时间（含复核、接管、返工）与端到端时长分开；另计模型、计算、设备及恢复成本 |
| 接管 | 发出至实际接收、接收到处置、恢复终态分别测量；缺乏权威终态时不标完成 |
| 人员能力 | 同类新案例独立诊断、解释、错误修正与延迟迁移；不要求在真实紧急事件中禁用安全工具 |

采用相同任务族与可比预算，按风险类别与案例难度比较；冻结 held-out 样本、保留全失败分母，测试者不以生成 Agent 的自评作为唯一 oracle。正式晋级前预先批准风险容忍与质量/成本阈值。任何观察到的越权、错误发布、无法对账副作用均阻断对应阶段晋级；零观察不等于风险为零，不用小样本宣称安全。若低风险规则已解决问题、Agent 没有净收益，保留规则而不扩大 Agent。

G5 的研究依据为 [[20261007-google-patent-lawyer-skill-formation]] 所述律师随机试验，领域和时间窗不同；不能外推生信人员技能一定退化或改善。这里只借用测量分离，试点需另测真实工作质量与能力。

## 6. 决策结论与待核事实

当前建议：将 A 阶段作为第一项候选试点；B/C 尚需真实验收，不作上线批准。先确认任务系统是否有稳定对象 ID、独立的状态/QC 查询、可靠的重试与取消语义、真实责任人及可脱敏证据。若任何一项未满足，缩小任务范围或先补确定性基础设施。不要为了符合五门结构而额外建设不必要平台。

本文没有读取实际业务系统、事故日志或人员数据，没有运行生产/测试 Agent，不是医疗、临床或企业合规评估。EX-005 仍缺同一生产事件的真实效果闭环证据；CR-005 仍缺共同纵向队列。该验收契约只为后续可观察行动提供设计，不结案这些研究问题。
