# Agent Perception Gap（Agent 感知差）

> [!definition] 定义
> **Agent Perception Gap** 是同一个数字资源在人类界面与 AI Agent 输入管线中呈现的信息差异。人类主要消费渲染后的视觉与交互结果，Agent 还可能读取 DOM、元数据、无障碍标签、像素或工具提供的结构化表示。具体差异取决于 Agent 的感知接口，并非所有 Agent 都同时访问这些层。

## 感知差的具体表现

下表是条件性的风险面分类，不代表所有Agent读取完整DOM、像素底层或字体映射，也不证明特定内容会被模型识别、执行或造成外部效果。

| 信息层 | 人类看到 | Agent 看到 | 可被利用的方式 |
|--------|---------|-----------|---------------|
| HTML 结构 | 渲染后的文本和布局 | 完整的 DOM 树、注释、属性 | 在 `<!-- -->` 中嵌入指令 |
| CSS 视觉 | 颜色、大小、位置 | 样式规则、display:none 元素 | 把恶意文本放在看不见的区域 |
| 元数据 | （通常不显示） | aria-label、alt-text、meta tags | 把指令伪装成无障碍标签 |
| 图片 | 视觉画面 | 视觉编码或像素工具（依接口） | 视觉输入与解析差异；不假定模型能解码任意隐藏信息 |
| 字体 | 字形 | 文本抽取结果（依接口） | 字形与机器读取文本不一致；需验证实际解析管线 |
| 动态内容 | 渲染完成后的最终状态 | JavaScript 执行过程中的状态变化 | 检测 Agent 来访后动态注入陷阱 |

## 为什么感知差难以完全消除

1. **接口取舍**：很多 Agent 为了可靠操作会同时使用视觉与结构化表示。只保留截图可以减少部分隐藏 DOM 攻击面，但会损失链接、表格、可访问性树等机器可操作结构；反过来，开放更多结构化层也会扩大输入攻击面。

2. **渲染后输入不是通用替代**：截图或渲染后输入可以隔离部分 HTML 隐藏内容，但会牺牲结构化操作能力，也不能自动解决视觉注入、动态内容或服务端针对 Agent 的差异化响应。

3. **类比自动驾驶**：不同任务所需感知通道不同；多表示有价值但不是每个Agent都必需。

## 防御方向

- **最小必要表示**：按任务过滤无需读取的内容，保留有用可访问性信息与来源；不能机械删除所有隐藏元素或aria标签。过滤不是授权边界。
- **感知对齐验证**：比较"Agent 解析结果"和"渲染后视觉内容"的一致性——检测两者语义差异
- **来源与权限**：将网页/工具输出当不可信数据而非高权限指令；可信域名也可能被污染。实际动作须在资源端校验身份、任务权限及结果，内容筛查仅是辅助。

## 关键数据点

- Agent Traps提出利用人类感知、机器解析与动态渲染之间差异的分类；本轮仅核到公开索引摘要，SSRN正文/PDF均403，不能确认首创或作者完整论证。
- [Verma & Yadav, arXiv:2509.05831v3摘要](https://arxiv.org/abs/2509.05831v3)：280页含等量干净与注入版本，并非280个独立攻击；注入样本中Llama4 Scout超过29%摘要有明显变化，Gemma9B IT约15%。摘要变化不是工具执行或真实攻击成功率；未重审全文。
- 字形/文本映射差异和动态差异化响应是历史引用的潜在风险；本轮未复核Xiong及Zychlinski原始材料，不作为已验证实现或普遍效果。

## 前提与局限性

- 感知差的概念在 Agent Traps 论文中被明确提出，但本轮未完成系统综述，不能断言无独立量化研究；不同输入、任务与模型的结果不可直接合并
- 内容消毒层的可行性受限于计算成本——全量语义比对可能增加开销，应按风险评估，不能预设不可扩展
