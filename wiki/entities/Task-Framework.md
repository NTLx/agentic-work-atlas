# Task Framework（任务框架）

## 定义

Task Framework 是 Acemoglu 和 Autor 提出的技术变革分析框架——以"任务"（task）而非"职业"或"行业"为基本分析单元，将技术变革分为五种类型，用以判断技术对劳动者福利的差异化影响。该框架源自 Acemoglu 和 Restrepo 的任务模型（task model），在 Hamilton Project "Building Pro-Worker AI" 论文中被系统应用于 AI 方向评估。

## 五种技术变革类型

2026-11-28 复核 [NBER w34854](https://www.nber.org/papers/w34854) 与 [Hamilton Project 论文发布页](https://www.hamiltonproject.org/publication/paper/building-pro-worker-ai/)：原页误把资本增强和自动化合并为一类，从而制造了“第五类未展开”的不存在缺口。正式论文摘要明确列出五类（同一研究线）：

| 类型 | 分析对象 | 判断边界 |
|---|---|---|
| 劳动增强（labor-augmenting） | 提高既有劳动任务效率 | 不保证就业、工资或劳动份额增加 |
| 资本增强（capital-augmenting） | 提高既有资本任务效率 | 不等同用资本接管劳动任务 |
| 自动化（automating） | 资本接管原由劳动完成的任务 | 需区分任务替代与总体劳动需求 |
| 专业知识拉平（expertise-leveling） | 改变任务所需专长及可执行人群 | 可能扩大参与，也可能改变专家溢价 |
| 新任务创建（new task-creating） | 新增需要劳动者及专业知识的任务 | 作者框架分类为unambiguously pro-worker；不等于实际福利全面提高 |

## 关键数据点

- 五类来自正式论文摘要，不是本库自拟类别；框架是理论分析及政策建议，非统一实证效果量。
- 原“资本增强/自动化”“第五类未展开”的分类退役；历史研讨会摘要与正式论文不重复计为独立证据。

## 核心洞见

同一技术可以同时包含多类机制，任务重分配、劳动力需求、工资、工时、工作质量与分配结果应分别验证。历史农业、纺织、自动驾驶例子是作者类比，不从其直接推出单一政策因果或当前AI就业净效应。

## 前提与局限性

- 技术类型在实际产品中可能交叠；需明确反事实、分类单位、时间及收益分配。
- 新任务存在不等于劳动者获得收益；应衡量就业、工资、劳动份额、职业发展、工作质量与安全。
- 未完整审查正式论文全部模型和历史案例，不将作者政策主张当作已验证政策效果。
